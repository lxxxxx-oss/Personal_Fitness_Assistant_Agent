# 面试前十分钟速记

这篇只用于面试前快速唤醒记忆，不承担第一次教学。

## 一句话定位

> 我设计了一个面向个人健身场景的多任务智能体，用 LangGraph 组织路由和子工作流，把知识检索、实时搜索、动作分析、外部工具和记忆系统整合成可解释、可评测、可降级的执行流程。

## 三十秒介绍

> 健身问题可能需要专业知识、最新资料、动作计算或外部工具，如果全部交给一次大模型回答会很难控制。我把系统拆成控制层和能力层：Router 判断任务，LangGraph 编排流程，RAG、Tavily、Motion 和 MCP 分别完成不同任务；Memory、统一错误和评测负责上下文与稳定性。项目主要体现任务拆分、工具编排和工程边界意识。

## Agent 核心三层（访问层在外）

| 层次 | 一句话 | 技术 |
|---|---|---|
| 控制层 | 决定任务怎样流转 | LangGraph、StateGraph、Router |
| 能力层 | 完成检索、搜索、计算和工具调用 | RAG、SQLite + FAISS、Tavily、Motion、ToolRegistry、MCP |
| 保障层 | 管理上下文、失败和质量 | Memory、PromptBuilder、ToolResult、fallback、测试与评测 |

## 三个主打亮点

1. **受控编排**：不同问题进入不同子工作流，多意图只执行白名单组合。
2. **大模型与确定性能力分工**：知识交给检索，最新信息交给搜索，动作交给数值算法。
3. **质量闭环**：路由有评测集，工具有统一错误和审计，RAG 与 Memory 有专项 benchmark。

## 六个高压问题

### 为什么不是聊天套壳？

> 因为系统会判断任务、选择工作流、调用检索或工具、执行数值计算，并根据执行结果回答。

### 为什么 Router 不全部交给大模型？

> 明确任务使用确定性策略更稳定、快速和可解释；模型只有带来评测收益时才值得启用。

### LangGraph、ToolRegistry 和 MCP 有什么区别？

> LangGraph 管业务流程，ToolRegistry 管工具执行，MCP 管外部工具协议。

### SQLite 和 FAISS 分别做了什么？

> SQLite 持久化正文、来源、章节和向量，是可审计的事实来源；FAISS 在进程内建立向量索引并做相似度搜索。它们都不负责生成回答，也不自动保证 RAG 质量。

### 为什么用 BM25 + RRF？

> Dense 擅长同义表达，BM25 擅长动作名、缩写和数字等精确词项；RRF 按名次融合，不必直接比较两种不同量纲的分数。当前先验证低成本混合召回，是否增加 reranker 由真实评测收益决定。

### RAGAS 三项怎么记？

> 上下文相关性看资料找得对不对，忠实度看回答有没有脱离资料乱说，答案相关性看有没有直接回答问题。42 条可回答 tuning 的本地 RAGAS 由 `1.000/0.725/0.788` 复测到 `1.000/0.897/0.798`，主要证明 `grounded-v3` 改善了忠实度；人工复核仍有排序问题、小模型越界和量化裁判假阴性，所以冻结参数后还要跑 18 条可回答 holdout，不把调参分数包装成最终高分。

### RAG 链路用了哪些模型？

> bge-small-zh-v1.5 负责运行时文档和查询向量化，Qwen3-0.6B 负责运行时证据回答，Qwen3-8B 只负责离线 RAGAS 裁判。当前能背的结果是：Dense 与 Hybrid 的 `Recall@5` 都是 `0.967`；MRR 分别是 `0.844` 和 `0.895`。也就是 Hybrid 没增加 Top-5 覆盖，但把正确证据平均排得更靠前。

### BM25、RRF、MRR 一句话区别？

> BM25 是关键词检索；RRF 是线上把 Dense 和 BM25 的排名融合起来；MRR 是离线评测正确证据排得靠不靠前。记成：BM25 负责“按词找”，RRF 负责“怎么排”，MRR 负责“排得好不好”。

### 视频能上传是否等于专业动作纠错？

> 当前能生成姿态序列、比较参考样本并输出结构化反馈；专业级纠错还需要正式样本、动作周期、关节规则和教练评测。

### 自动化测试数字能证明什么？

> 它证明代码契约和核心链路可回归，不直接等于真实回答质量；策略效果要看专项评测。

## 当前边界

- 本地面试原型，不直接暴露公网。
- 没有完整认证、限流、租户隔离和生产级隐私治理。
- MCP 默认 mock，协议和进程治理仍可增强。
- Motion 相似度不等于医疗或专业教练诊断。
- Docker 和小程序仍需跨机器、真机和弱网完整验收。

> 这个项目最想证明的是：我知道什么问题该交给大模型，什么问题该交给知识、搜索、算法或工具，并能用受控流程、错误治理和评测把它们组织成一个完整系统。
