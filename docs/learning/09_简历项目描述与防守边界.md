# 简历项目描述与防守边界

本文只保留当前可使用的简历表述和追问边界。学习概念看[简历技术点总表](./03_简历技术点总表.md)，测试数字看[项目证据](../project/项目证据.md)；这里不再保存已经淘汰的多版草稿。

## 使用规则

- 简历写已经实现且有证据的主线，不堆所有内部细节。
- 面试先讲价值和方案，再主动说明原型边界。
- 评测数字可能变化，提交简历前从项目证据核对，不在多处维护。
- “可选、默认关闭、待完整验收”的能力不能说成默认生产能力。

## 1. 混合意图路由

### 当前推荐表述

> **构建可评测的混合意图路由**：基于 LangGraph StateGraph 组织五类执行路径，以加权规则、组合模式和置信度降级稳定处理业务边界，并识别主意图、次意图与执行计划；无规则形成稳定结论时保留可选 embedding 样例匹配，可靠复合任务按用户表达顺序串联合法子图，并使用常规、困难和语义改写集持续回归。

### 证据与边界

- 已实现加权规则、歧义信号、可解释评分、主/次意图，以及开放合法组合的顺序执行；计划会过滤非法意图、去重并限制最多三步。
- 每步结果与异常独立记录，部分失败时保留成功步骤并继续，最终由 synthesis 统一合成；这不是会自由创建循环和依赖关系的开放式 Planner。
- embedding 样例匹配有置信度和 Top1-Top2 margin 门控；本地 Qwen classifier 是独立 A/B 实验路径。
- embedding 和 Qwen 默认关闭，因为现有小样本没有证明它们比确定性基线更好。
- 离线满分只说明当前样本没有回归，不代表生产流量泛化完成。

追问时强调：规则保护“用户要求系统做什么”的工具边界，embedding 更擅长主题相似，不能无条件替换规则。

## 2. 3D 运动动作相似度分析

### 当前推荐表述

> **实现可解释的动作相似度分析原型**：使用 MediaPipe 与 OpenCV 将图片、短视频转换为统一 PoseSequence，对 3D 关键点序列进行平移/尺度归一化、FastDTW 时序对齐、余弦和形状差异比较，并输出膝髋角度误差、最大偏差关节/帧及低置信质量提示。

### 证据与边界

- 图片、视频和 `.npz` 已统一到带 schema、坐标空间、置信度和 FPS 的 `PoseSequence`。
- 已有全局相似度、局部关节距离、深蹲膝髋角误差和质量门控。
- “3D”指单目 MediaPipe 的 `x/y/z` 或 world landmarks，不是多摄像头专业动捕。
- 正式标准/典型错误动作集、动作周期切分、阶段规则和教练标签校准尚未完成，因此不能称为专业评分模型。

追问时强调：数值链路可重复、可定位错误；多模态大模型更适合作为后续解释层，而不是替代关键点和时序指标。

## 3. SQLite + FAISS 混合 RAG

### 当前推荐表述

> **构建可追溯、可评测的健身领域混合 RAG 链路**：以 SQLite 持久化父子分块、来源及向量，使用 FAISS 承载 BAAI/bge-small-zh-v1.5 Dense 检索，并与 BM25 候选经 RRF 融合、父块回填和同父去重，为所选模型提供最多 Top-5 证据；接入 RAGAS，从上下文相关性、回答忠实度与答案相关性三个维度评估 RAG 质量。

### 证据与边界

- Chat/Diet 复用同一 Retriever，检索来源会进入回答元数据。
- SQLite 是 chunk、来源、章节和 float32 向量的持久化事实来源；进程启动后从数据库重建归一化 `FAISS IndexFlatIP`，无需重新 embedding。同一来源重新入库时事务替换旧 chunk，并检查 embedding 模型与向量维度，避免索引静默混用。
- 运行时与离线角色必须分清：`BAAI/bge-small-zh-v1.5` 负责文档和查询向量化，用户选择的本地 Qwen 或 DeepSeek API 模型负责依据证据生成回答；历史离线评测中的 `Qwen3-8B` 仅作为 RAGAS 裁判，不参与运行时回答。
- 当前选择确定性的结构感知父子分块：父块默认 500/80、检索子块 300/50，小块负责匹配、父块负责补全语境；Dense 与 BM25 默认各召回 20 条子块，融合前不做固定相似度硬过滤，经 RRF、父块回填和同父去重后返回最多 Top-5。LLM 语义切块和 reranker 尚未落地。
- 80 条黄金集中，60 条可回答样例进入三指标均分，20 条知识库外或证据不足问题单独保留；数据又拆为 55 条 tuning 和 25 条 holdout，并按难度、问题类型与主题分层，避免只看一个容易受偶然性影响的总分。
- Hybrid 与父子分块已有精确词项、数字、语义改写、干扰项、父块回填、同父去重、来源透传和降级契约测试。2026-08-08 当前父子版复测中，Dense/Hybrid `Recall@5=0.967/0.967`、`MRR=0.844/0.893`；42 条 tuning 与 18 条 holdout 的 RAGAS 分别为 `1.000/0.902/0.786`、`1.000/0.815/0.762`。它们能证明当前链路可复现、融合排序有效，但相对旧单层结果没有显著提升，不能称为父子分块带来了确定收益；holdout 更低还说明生成泛化与裁判稳定性需要继续人工校准。
- 当前是单机、小规模知识库的务实方案；SQLite + FAISS 不提供分布式服务、复杂标量过滤或多实例共享索引。生产规模扩大后可在保持 Retriever 接口不变的前提下迁移 Milvus、Qdrant 或 pgvector。持久化批次账本、Cross-Encoder 重排和大规模评测尚未完成。

追问时先按 `query -> Dense + BM25 子块召回 -> RRF -> 父块回填与同父去重 -> Top-5 contexts` 解释检索，再按 `contexts -> generate_node -> answer -> RAGAS judge` 解释评测。主口径只讲 RAGAS 的三个维度；如果面试官继续追问如何定位检索问题，再补充 Recall@K 看是否召回、MRR 看正确证据是否靠前，它们只是辅助诊断，不与 RAGAS 合成总分。

当前仍不建议把某一组 RAGAS 小样本分数直接写进简历。虽然当前父子版已经完成 18 条可回答 holdout 的首次冻结复测，但其忠实度和答案相关性低于 tuning，本地量化裁判也尚未用更多人工样本充分校准。简历优先写“建立分层黄金集并跑通 tuning/holdout 评测闭环”；Recall@K、MRR 与具体 RAGAS 数字保留在技术记录中，用于面试追问时解释检索方案和真实边界。

## 4. 分层记忆与上下文压缩

### 当前推荐表述

> **实现分层记忆与持久化上下文压缩机制**：将 SQLite 完整会话、结构化证据摘要、最近六轮原文和长期用户记忆分层管理；通过覆盖边界增量压缩历史，以有效期、置信度和同槽位替代治理长期事实，再按任务组合相关记忆与 RAG 证据构造 Prompt，摘要或可选语义索引失败时可降级。

### 证据与边界

- 完整 turn 事务写入，HTTP、SSE、WebSocket 共用持久化和 Prompt 构建入口。
- 长期记忆支持显式写入、隐式 observation、跨会话独立证据晋升、低信任软注入、事件撤销、精确去重、CRUD、有效期、同槽位替代和任务感知 SQLite FTS/LIKE 召回；敏感/冲突信息保留确认门，秘密信息零落库。
- 长期记忆默认使用任务感知的 SQLite FTS/LIKE 召回；可选的 SQLite + FAISS 派生索引用于增强语义召回且默认关闭。SQLite 仍是可修改、可删除、可审计的事实来源；索引重建当前通过本地 job 接口演示，不是常驻 worker。
- Chat 与 Diet 的核心回答 Prompt 会组合摘要、近期原文、相关长期记忆和 RAG 证据；Search、MCP 等分支只读取任务所需的上下文子集，不能说所有节点都注入全部记忆。
- active summary 是确定性结构化证据整理，字符和估算 token 双预算均不是模型级语义总结；本轮总输入预算由模型声明上限派生并在推理前由实际 tokenizer 校验，但 Prompt 区段尚未做精确 token 配额；隐式提取仅覆盖有限稳定句式，任意潜台词理解、加密授权和多实例治理未完成。

追问时强调：完整历史、当前会话进度和跨会话长期事实是三类不同数据，不能都塞进聊天窗口或都写进向量库。

## 简历提交前检查

1. 四项表述与当前代码状态一致。
2. 测试和评测数字从[项目证据](../project/项目证据.md)核对。
3. 默认关闭的实验能力明确写成“可选”或只在追问时解释。
4. 没有把代码级闭环写成生产上线，也没有把 tuning 调参基线写成 holdout 或生产结论。
