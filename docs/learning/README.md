# 智能体岗位面试学习中心

这里不是代码 Agent 的维护手册，而是一套供你本人使用的学习与面试课程。目标是让你先理解，再表达，最后能够应对追问。

项目的当前实现、接口、运行方式和测试证据统一放在[代码 Agent 项目资料中心](../project/README.md)；本目录只负责把这些事实转化为容易理解、可以复习且能够防守的表达。

## 岗位范围与难度梯度

这套资料主要面向校招的“智能体应用开发”和“全栈智能体开发”。公司规模不作限制，因此既准备小团队关心的快速落地，也准备中大型公司关心的可靠性、评测、安全和系统设计。

| 难度 | 常见阶段 | 你要做到什么 |
|---|---|---|
| 基础级 | 一面概念题 | 用普通话解释是什么、解决什么问题 |
| 项目级 | 项目深挖 | 讲出真实调用链、数据结构、取舍和代码证据 |
| 工程级 | 二面或系统设计 | 分析故障、指标、安全、扩容和生产化方案 |

不要跳过基础级直接背工程术语。渐进式学习的目标不是每道题都答得很长，而是面试官继续追问时，每一层都有新信息。

## 每个知识点的讲透标准

每项核心技术至少要能回答九件事：它是什么；解决什么问题；在本项目的入口、执行和输出；采用了什么数据结构或参数；替代方案与选型理由；常见失败模式；当前怎样处理失败；用什么指标证明有效；生产化先补什么。前五项证明你理解技术，后四项证明你有工程意识。

## 先别试图一次读完十二篇

真正的主线只有四篇：项目地图、项目话术、技术点总表和高频问答。其余都是按需查阅材料。推荐按下面节奏学习：

| 时间 | 只做什么 | 达标标准 |
|---|---|---|
| 第一次 60—90 分钟 | 读 01、02，并口述一次 30 秒介绍 | 不看文档也能讲清“为什么需要路由和分工” |
| 第二次 60 分钟 | 从 03 只学 Router、RAG、MCP、Memory 四条简历主线 | 每条能回答“是什么、怎么用、为什么选、边界” |
| 第三次 45 分钟 | 用 04 和 08 做连续追问 | 第一回答控制在 20—40 秒，追问再补细节 |
| 面试当天 10 分钟 | 只看 07 | 唤醒结构和数字，不再学习新知识 |

05、06、09、10 是专题资料，只有面试官或简历重点涉及对应主题时再展开。这样可以先形成稳定主线，再逐步增加深度。

## 学习目标分为四级

### 第一级：能听懂

你能用生活化语言解释：

- 智能体与普通聊天机器人有什么区别。
- 为什么系统需要先判断任务。
- 为什么不同问题要交给不同能力。

对应文档：[零基础项目地图](./01_零基础项目地图.md)。

### 第二级：能讲清

你可以完成：

- 一句话项目定位。
- 30 秒项目介绍。
- 3 分钟完整项目故事。
- 三个核心亮点和个人贡献。

对应文档：[项目讲解与面试话术](./02_项目讲解与面试话术.md)。

### 第三级：能解释

每项核心技术都可以回答：

1. 它是什么。
2. 它解决什么问题。
3. 项目中怎样使用。
4. 有哪些替代方案。
5. 为什么选择当前方案。

对应文档：[简历技术点总表](./03_简历技术点总表.md)和[高频技术问答](./04_高频技术问答.md)。

### 第四级：能防守

面对连续追问时，你能：

- 先给结论，再解释原因。
- 画出数据流和模块关系。
- 说明当前做到哪里。
- 说明生产化如何升级。
- 承认合理边界，但不主动削弱项目价值。

对应文档：[技术深挖与白板](./06_技术深挖与白板.md)、[模拟面试](./08_模拟面试.md)和[记忆与上下文专项追问](./10_记忆与上下文专项追问.md)。

## 统一回答结构

所有技术问题尽量使用同一套结构：

```text
结论
  -> 业务问题
  -> 方案怎样工作
  -> 为什么选择它
  -> 结果、边界与下一步
```

例如，面试官问“为什么使用 LangGraph”，可以回答：

> 因为这个项目不是单一问答，而是要在知识检索、联网搜索、动作分析和外部工具之间选择流程。LangGraph 把每一步表示成明确节点，让路由结果、工具结果和错误都保存在共享状态中。相比一个巨大 Prompt，它更容易控制和测试；相比完全自主的多智能体方案，它更适合健康场景对稳定性的要求。

真实面试中第一轮不要一次把所有层次全说完。先用 20—40 秒给结论、项目做法和一个取舍；面试官继续问时，再补代码路径、指标和生产化方案。被打断通常说明对方想深入某一点，不代表回答失败。

## 完整架构分四层，Agent 核心先记三层

| 层次 | 负责什么 | 代表技术 |
|---|---|---|
| 接入层 | 接收请求并把结果返回给用户 | FastAPI、HTTP、SSE、WebSocket、Web、小程序 |
| 控制层 | 决定任务怎样流转 | LangGraph、StateGraph、Router |
| 能力层 | 完成检索、搜索、计算和工具调用 | RAG、SQLite + FAISS、Tavily、Motion、ToolRegistry、MCP |
| 保障层 | 管理上下文、失败和质量 | Memory、PromptBuilder、ToolResult、fallback、测试与评测 |

接入层负责“用户怎样进来”，后三层才是 Agent 的核心：控制层选择流程，能力层完成任务，保障层让流程更可靠。第一次学习可以先记后三层；讲完整架构时再补上接入层。

## 三种表达口径

| 口径 | 什么时候讲 | 示例 |
|---|---|---|
| 价值口径 | 开场和业务问题 | 系统能根据问题选择知识、搜索、算法或工具 |
| 设计口径 | 技术追问 | Router 生成路由计划，LangGraph 调度子工作流 |
| 边界口径 | 深入追问 | 当前是可运行原型，生产化还需权限、监控和数据闭环 |

不要一开场就说“只是原型”，也不要把未来规划说成已经全面上线。先展示核心设计，再在被追问时说明证据和边界。

## 四种能力状态必须分清

学习每个技术点时，先判断它属于哪一种状态：

| 状态 | 含义 | 表达示例 |
|---|---|---|
| 默认启用 | 正常启动即可进入主链路 | Dense + BM25 + RRF 是默认 RAG 检索方式 |
| 可选能力 | 代码已经接入，但需配置开启 | 长期记忆的语义 FAISS 索引默认关闭 |
| 调参与复测已完成 | 训练/调参分区的结果用于定位问题，不等于留出集验收或生产结论 | 80 条分层黄金集和 RAGAS 入口已接通；60 条可回答样例的 Dense/Hybrid 检索诊断已记录，`grounded-v3` 使 42 条可回答 tuning 的 RAGAS 结果由 `1.000/0.725/0.788` 变为 `1.000/0.897/0.798`，18 条可回答 holdout 尚未运行 |
| 生产化方向 | 当前未完整落地，只用于说明演进思路 | 持久化审计、细粒度鉴权和资源隔离 |

这四种状态不是能力高低排序，而是事实边界。面试时说清状态，既能保留亮点，也不容易在追问中把“有代码”误说成“全程启用”或“已完成实验”。

## 学习检查

如果下面五个问题还不能脱离文档回答，就先不要继续背更多名词：

1. 这个项目为什么算智能体？
2. 用户提出问题后，系统依次做什么？
3. 为什么大模型不能包办所有任务？
4. 路由、工具注册表和 MCP 分别负责什么？
5. 怎样证明系统不是“看起来能用”，而是真的可验证？
