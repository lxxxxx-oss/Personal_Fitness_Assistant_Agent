## 当前测试结论

- 动态会话摘要水位专项回归（2026-08-17）：跨请求 active summary 不再对所有模型固定使用 `3000` 字符/`900` Token 触发线，而是从模型上下文上限派生最大 Prompt 预算与主动 compact 线 `T`，再按 `clamp(floor(T×0.35), 900, 4000)` 计算摘要 Token 水位，字符水位默认同步为 4 倍；显式环境变量仍可覆盖自动结果，运行结果会返回实际使用的双阈值便于排错。专项关联回归 `72 passed, 1 warning`；全量 `python -m pytest -q` 为 `369 passed, 1 skipped, 3 warnings`，用时 `100.91s`。该结果证明预算派生、配置覆盖、增量摘要和既有上下文链路没有回归，不代表 `35%` 与上下限已经是线上长对话的最优参数。
- Agent 安全策略专项回归（2026-08-11）：所有 LLM 入口统一接入版本化全局规则 `global-safety-v1`，子图只追加更严格的领域约束；用户、记忆、RAG、网页和工具内容统一按不可信数据处理。非流式出口与 SSE/WebSocket 句段级流式出口复用同一输出校验，覆盖内部推理清理、常见秘密脱敏、高置信系统提示泄露和医疗越界阻断，并记录安全版本与命中轨迹。`python -m pytest tests/test_safety_policy.py -q` 为 `11 passed, 1 warning`；全量 `python -m pytest -q` 为 `363 passed, 1 skipped, 3 warnings`，用时 `51.34s`。新增测试还确认上下文压缩不会删除全局规则、子图规则和当前问题。该结果证明应用层规则合并与输出边界可以回归，不代表系统已经具备生产级内容审核、身份鉴权、工具沙箱或医疗安全认证。

> 我没有只做功能演示，而是给关键 Agent 能力补了可回归证据。Router 有离线 eval、challenge set 和语义改写集；RAG 用同一黄金集先比较 Dense/Hybrid 的检索指标，再让真实检索与生成链路进入 RAGAS 三维评测；Motion 有真实图片/视频姿态链路和可解释指标回归；工具系统记录 execution_id、耗时、重试和 fallback；Memory + Context + RAG 还有统一 benchmark，验证多个模块组合后没有回归。

## RAGAS 结果怎样解读

- 上下文相关性低：Hybrid 优先检查分块、embedding、候选预算和 RRF；纯 Dense 再检查 Top-K 与阈值，问题主要在 Retriever。
- 忠实度低：检索资料可能足够，但生成回答加入了上下文无法支持的内容，问题主要在 Prompt 或生成模型。
- 答案相关性低：回答可能没有胡编，却没有直接、完整回答原问题，属于端到端表达问题。
- 三项分数用于定位问题，不合并成一个“总准确率”；小样本分数也不能外推为线上质量。
- 20 条无答案样例暂不进入三项均分，避免把正确拒答错误解释为上下文不相关；检索报告单独记录空结果率。当前两种检索都会返回 Top-5，因此空结果率为 0，这不是最终回答的拒答准确率，后续应在生成阶段另设判定口径。
- 父子分块前 42 条 tuning 的 `grounded-v3` 均分是上下文相关性 `1.000`、忠实度 `0.897`、答案相关性 `0.798`，相对原始基线 `1.000/0.725/0.788` 主要改善忠实度；2026-08-08 父子索引 v2 的 tuning 为 `1.000/0.902/0.786`，当前层级聚合 v3 尚未复测。`ContextRelevance` 对拼接后的 Top-5 上下文整体做两次离散判断，因此全为 `1.000` 只能说明裁判认为整组资料足以回答，不能证明每个 chunk 都无噪声，也不能替代 Recall@K/MRR。
- 本地 8B 裁判并非绝对真值：复测既保留了真实排序/生成问题，也出现正确回答被 `AnswerRelevancy` 或 `Faithfulness` 压到 0 分的情况。面试时应说“已完成当前版本 tuning 与首次 holdout，并结合失败样例人工抽检；holdout 暴露了生成端泛化波动”，不能把小样本分数包装成生产质量或显著提升。
