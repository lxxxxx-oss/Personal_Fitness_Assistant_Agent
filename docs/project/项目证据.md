## 怎么回答“你怎么证明项目不是玩具项目”

可以这样说：

> 我没有只做功能演示，而是给关键 Agent 能力补了可回归证据。Router 有离线 eval、challenge set 和语义改写集；RAG 用同一黄金集先比较 Dense/Hybrid 的检索指标，再让真实检索与生成链路进入 RAGAS 三维评测；Motion 有真实图片/视频姿态链路和可解释指标回归；工具系统记录 execution_id、耗时、重试和 fallback；Memory + Context + RAG 还有统一 benchmark，验证多个模块组合后没有回归。

## RAGAS 结果怎样解读

- 上下文相关性低：Hybrid 优先检查分块、embedding、候选预算和 RRF；纯 Dense 再检查 Top-K 与阈值，问题主要在 Retriever。
- 忠实度低：检索资料可能足够，但生成回答加入了上下文无法支持的内容，问题主要在 Prompt 或生成模型。
- 答案相关性低：回答可能没有胡编，却没有直接、完整回答原问题，属于端到端表达问题。
- 三项分数用于定位问题，不合并成一个“总准确率”；小样本分数也不能外推为线上质量。
- 20 条无答案样例暂不进入三项均分，避免把正确拒答错误解释为上下文不相关；检索报告单独记录空结果率。当前两种检索都会返回 Top-5，因此空结果率为 0，这不是最终回答的拒答准确率，后续应在生成阶段另设判定口径。
- 42 条 tuning 的当前 `grounded-v3` 均分是上下文相关性 `1.000`、忠实度 `0.897`、答案相关性 `0.798`，相对原始基线 `1.000/0.725/0.788` 主要改善忠实度。`ContextRelevance` 对拼接后的 Top-5 上下文整体做两次离散判断，因此全为 `1.000` 只能说明裁判认为整组资料足以回答，不能证明每个 chunk 都无噪声，也不能替代 Recall@K/MRR。
- 本地 8B 裁判并非绝对真值：复测既保留了真实排序/生成问题，也出现正确回答被 `AnswerRelevancy` 或 `Faithfulness` 压到 0 分的情况。面试时应说“已完成 tuning 前后对照并人工抽检；证据约束改善了忠实度，冻结配置后再跑 holdout”，不能把 tuning 分数包装成最终泛化效果。
