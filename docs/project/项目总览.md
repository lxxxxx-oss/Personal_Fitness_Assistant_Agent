# 个人健身助手智能体项目总览

本文档是当前项目事实的唯一总入口。它负责说明项目是什么、代码已经做到哪里、有哪些证据、还存在哪些边界。

如果你的目标是准备面试，不要从本文开始背诵，请先阅读[文档总导航](../README.md)；如果需要学习项目话术，请阅读[项目讲解与面试话术](../learning/02_项目讲解与面试话术.md)。

## 1. 项目定位

项目的第一目标是服务智能体相关岗位面试。健身、营养和动作分析是业务场景，真正要展示的是：

- 怎样判断用户意图并选择流程。
- 怎样让大模型与知识库、搜索、算法和外部工具协作。
- 怎样管理状态、上下文和长期记忆。
- 怎样处理工具失败、依赖降级和结果追踪。
- 怎样用测试和评测验证系统。

一句话描述：

> 这是一个基于 LangGraph 的多任务智能体原型，通过受控路由把领域知识检索、实时搜索、动作分析、外部工具和记忆系统组织成可解释、可评测、可降级的执行流程。

## 2. 总体架构

系统分为四层：

```text
接入层
  FastAPI / HTTP / SSE / WebSocket / Web UI / 微信小程序
      ↓
控制层
  Router / LangGraph / 路由计划 / 子工作流
      ↓
能力层
  Knowledge / Search / Motion / MCP / ToolRegistry
      ↓
保障层
  Memory / PromptBuilder / ToolResult / fallback / 测试与评测
```

各层职责：

| 层次 | 负责什么 | 不负责什么 |
|---|---|---|
| 接入层 | 接收请求和返回结果 | 决定任务应该怎样执行 |
| 控制层 | 判断意图、选择流程、维护共享状态 | 完成具体检索或计算 |
| 能力层 | 检索知识、搜索网络、计算动作、调用工具 | 决定整个业务流程 |
| 保障层 | 管理上下文、错误、降级和质量证据 | 替代业务能力本身 |

## 3. 用户请求怎样流转

### 普通文本请求

```text
用户问题
  -> FastAPI 接收请求
  -> Router 识别主意图、次意图和置信度
  -> 生成单路由或白名单组合计划
  -> LangGraph 调用对应子工作流
  -> 子工作流调用知识、搜索、工具或模型
  -> 写回回答、来源、警告和执行轨迹
  -> 返回最终结果
```

### 图片或视频动作请求

```text
图片 / 视频 / .npz
  -> 独立动作分析接口
  -> 姿态估计或数值文件解析
  -> 统一 PoseSequence
  -> 可选标准动作比较
  -> 结构化动作结果与提示
```

媒体上传通过独立接口执行；对话 Router 仍可以识别动作相关文本，并进入 Motion 子工作流进行规划和解释。

## 4. 当前能力状态

### 4.1 路由与图编排

当前实现：

- 顶层使用 LangGraph StateGraph 组织路由和子工作流。
- Router 支持 `search`、`motion`、`diet`、`chat`、`mcp` 兼容意图。
- 产品层将 Chat 与 Diet 统一为 Knowledge 能力域；代码层仍保留 `chat`、`diet` 两个兼容分支，分别处理普通问答和饮食建议，并共用 RAG 与上下文组件。
- 支持主意图、次意图、置信度和受控两步组合。
- 当前白名单组合为 Search + Diet、Search + Chat、Motion + Chat、Motion + Diet。
- 低置信路径已接入可选 embedding 样例匹配，默认关闭；当前 10 条语义改写集只能证明入口可回归，还需要更大的同义改写、hard negative 和延迟评测证明净收益后再启用。
- 本地 Qwen 分类器已完成对比验证，但默认关闭。

设计取舍：明确问题优先使用可解释、低延迟的确定性策略；复杂组合不开放任意规划，只执行经过测试的白名单。

### 4.2 领域知识与饮食建议

当前实现：

- 本地知识库包含 12 份可索引的 `.txt/.md` 结构化文档，覆盖抗阻训练、身体活动、运动蛋白、肌酸、健康膳食、体重管理、运动补液和睡眠恢复；来源包括 WHO、CDC、ACSM、中国居民膳食指南、ISSN、NIDDK、NATA 和 AASM。内容为带来源、核验日期、适用范围和安全边界的中文摘要，不直接复制整页网页或论文。
- 分块器先识别 Markdown 标题层级，再按段落和中英文句子边界装箱；超长句才硬切分，普通相邻块也会保留可配置的真实重叠。默认每块最多 500 字符、重叠约 80 字符。
- 每个 chunk 保留 `section_path`；编码时将章节路径与正文一起表示，生成 Prompt 时也展示章节位置，短段落因此仍带有主题信息。公开 API 的 `sources` 继续只返回文件来源，不改变接口契约。
- Retriever 默认采用 Hybrid 策略：Dense 向量检索与 BM25 各召回 20 条候选，经 RRF（倒数排名融合）合并、去重后返回 Top-5；也可通过配置切回纯 Dense。默认 Dense 后端为 SQLite + FAISS，也可切到纯内存模式。
- 默认 embedding 统一为 512 维 `BAAI/bge-small-zh-v1.5`。SQLite 持久化 chunk、来源、章节、模型信息和 float32 向量；进程启动后从 SQLite 重建 FAISS `IndexFlatIP`，对归一化向量执行余弦近邻搜索。
- SQLite + FAISS 后端支持稳定主键、幂等写入、同源片段事务替换和模型/维度一致性校验；重新启动后无需重新编码即可恢复索引，避免新旧知识版本混杂。
- 入库结果会返回轻量 manifest，记录知识版本、来源、章节路径、chunk 数、chunk id 和内容哈希，便于面试时说明知识更新如何追踪。
- Chat 和 Diet 共用统一检索配置。Hybrid 主链路在融合前不做固定相似度硬过滤，Dense 与 BM25 使用相同候选预算后交给 RRF；相似度阈值只保留给纯 Dense 模式和对照评测。融合结果记录两路各自分数、排名、命中路线、来源和章节，再经去重、编号后进入 Prompt；本地持久化后端初始化、写入或检索失败时可降级到内存向量检索，并在执行轨迹中标记 `degraded`。
- 已建立 21 条 RAG 黄金集，其中 19 条可回答、2 条知识库外问题。项目以 `scripts/eval_rag.py` 的三项 RAGAS 结果作为对外主评测口径；`scripts/eval_retrieval.py` 不调用生成模型，仅用 Recall@K、MRR 和延迟辅助定位 Dense/Hybrid 的召回与排序问题，不与 RAGAS 合成总分。两条入口均已完成代码与单元测试，本机尚未运行 19 条完整 RAGAS。
- Knowledge 和 Diet 的检索通过 ToolRegistry 中的 `knowledge.retrieve` 执行。
- 饮食画像经过 JSON 解析和 Pydantic 范围、枚举校验。
- 非法画像不会直接进入推荐链路，而是降级为空画像并产生警告。

当前边界：这次升级采用确定、可复现的结构感知分块与 RRF 排名融合，没有引入 LLM 语义切块、父子索引或 reranker；当前规模下更容易调试，也能先验证混合召回是否值得增加重排成本。知识扩充采用人工筛选权威来源、结构化改写和本地入库，不是定时联网爬虫；当前知识目录只索引 `.txt/.md`，尚未接入 PDF 解析。SQLite + FAISS 适合本项目的单机、小规模语料，不提供分布式扩缩容或服务端索引治理；生产规模增长后可在不改变上层 Retriever 契约的前提下迁移到 Milvus、Qdrant 或 pgvector。12 份文档经分块 v2 得到 81 个 chunk；2026-07-22 本地 BGE 的 `19/19` 是旧纯 Dense 历史冒烟，不代表 Hybrid 已优于 Dense。RAGAS 裁判 LLM 与 embedding 已解耦，本地 Qwen3-8B 配合 BGE 只完成单条兼容性烟测；真实 Dense/Hybrid 检索指标和 19 条完整 RAGAS 均需在模型可用电脑运行后记录。21 条黄金集仍属于小样本，逐句引用、生产级批次回滚和大规模评测仍可增强。

### 4.3 联网搜索

当前实现：

- 先理解并改写查询，再调用 Tavily，最后合成回答。
- 搜索结果保留标题、摘要和网址。
- 未配置密钥时可以使用演示结果。
- Search 已通过 ToolRegistry 中的 `search.tavily` 调用。
- 真实调用失败会返回可处理错误和降级信息。

当前边界：现有来源约束不等于逐句引用完全正确，后续仍需来源可信度和引用校验。

### 4.4 动作分析

当前实现：

- 支持 `.npz`、图片和短视频输入。
- MediaPipe 可将图片和视频帧转换为 33 点人体姿态。
- OpenCV 负责视频读取和抽帧。
- PoseSequence 统一保存关键点、帧率、模型、关节结构和置信度。
- 支持与兼容标准样本进行 FastDTW、余弦、对齐后逐关节平均距离、最大偏差关节/帧定位和 MediaPipe 膝/髋角度误差计算。
- 支持用关键点置信度过滤低质量关节；当有效对齐比例不足时返回低置信 warning 和 `quality.accepted=false`，全部关键点都不可用时才拒绝输出相似度结论。
- 支持从标准视频离线构建标准动作文件。
- 不兼容的姿态模型或关节结构会被拒绝。
- `motion.compare_pose` 已登记到 ToolRegistry，但媒体接口仍由 API 和 LangGraph 直接控制。

当前边界：相似度和角度误差表示与参考样本的统计接近程度，不等同于专业教练或医疗诊断；正式动作库、周期切分、阶段级专项规则和教练标签仍需扩充。

### 4.5 工具系统与 MCP

当前实现：

- 使用统一 `ToolResult` 和 `ErrorCode` 表达成功、失败和错误类型。
- ToolSpec 描述工具名称、说明、输入结构、权限、执行器、超时策略字段、重试和 fallback。
- ToolRegistry 支持注册、列出、参数校验、权限检查、有限重试、fallback 和审计。
- 每次执行记录 `execution_id`、`duration_ms`、尝试次数和降级来源。
- 默认登记知识检索、Tavily 搜索、动作比较和 MCP 调用四类代表工具。
- Search、Knowledge/RAG 和 MCP 执行路径已经接入注册表。
- MCP Client 支持子进程、标准输入输出、JSON-RPC 初始化、工具列表和工具调用主链路。
- 默认 MCP 使用 mock，保证本地演示稳定。

当前边界：注册表的 `timeout_seconds` 目前是策略元数据，不会强制中断长时间执行；MCP 的响应编号匹配、深层参数校验、进程隔离和真实服务兼容性仍需增强。

### 4.6 记忆与上下文

当前实现：

- 滑动窗口保存近期对话。
- 会话消息和长期记忆写入本地 SQLite。
- 会话摘要存储基础已接通：完整问答按单事务写入，active summary 可替换，`last_compacted_message_id` 记录摘要覆盖边界，并按用户与会话隔离读取。
- 已实现确定性的结构化证据摘要：只复用原始消息片段，将目标、约束、偏好映射到可追溯证据，按字符和估算 token 双阈值触发与限长，复用上一版 active summary，并与滑动窗口统一保留最近六轮原文。
- HTTP、SSE 和 WebSocket 共用会话准备与成功 turn 持久化入口；生成失败返回结构化错误且不写入历史。下一次请求会加载 active summary，并在 Chat、Diet、Search 和 MCP 最终 Prompt 中与最近对话、长期记忆分区注入。
- 长期记忆支持 CRUD、有效期、置信度、同槽位冲突替代和派生向量删除同步；检索会排除未生效、已过期或已删除记录，并结合任务类型调整排序。
- Memory Writer 支持显式“记住……”和少量稳定表达：普通显式内容直接写入长期记忆；低风险隐式信息先进入 observation，跨会话独立证据和置信度达标后自动晋升，晋升前只能作为不确定线索软注入；健康等敏感内容需要确认，口令、令牌等秘密信息拒绝持久化。
- 记忆管理页可以查看、删除正式记忆，确认或拒绝 observation，并审计、撤销可逆事件；临时对话只使用进程内最近窗口，不读取和写入持久化记忆。
- 主记忆库 SQLite 是会话和长期记忆的事实来源；可选语义增强使用独立 SQLite 向量库与进程内 FAISS 索引，默认不开启，不影响主链路。
- PromptBuilder 集中组织近期对话、active summary、长期记忆、知识证据和任务信息。
- 当前存在两类上下文压缩：回答保存后的持久化 active summary，用于跨请求保留较早会话；PromptBuilder 的本轮 prompt compact，会按标题区段保留角色/规则、结构化摘要和用户问题，避免原始字符切片破坏语义边界，并记录长度和压缩轨迹。
- 本轮 Prompt 预算不再使用固定经验值：启动时读取本地模型声明的上下文窗口，扣除最大生成 token 与安全余量后得到输入硬预算，默认在其 80% 主动压缩；PromptBuilder 用保守估算提前控制长度，LLMLoader 在 chat template 后用真实 tokenizer 做最终边界校验。

当前边界：会话摘要是规则驱动的结构化证据整理，不具备模型级语义归纳能力；持久化摘要和 PromptBuilder 的提前压缩仍使用保守 token 估算，只有真正推理前的最终边界使用实际 tokenizer。模型元数据不可用时会回退到安全配置，此时不能声称已测得真实上限。摘要更新也没有多实例并发锁。摘要失败不会阻塞聊天，系统继续使用最近滑动窗口和本轮临时 compact。隐式记忆只覆盖少量稳定句式，不宣称理解任意潜台词；自动晋升参数是待评测校准的原型默认值。向量同步通过本地处理接口演示，不是常驻后台 worker；登录鉴权、用户授权、加密和生产级隐私治理尚未完成。

### 4.7 接口与客户端

当前实现：

- FastAPI 提供非流式 HTTP、SSE 和 WebSocket 对话接口。
- 三种聊天传输共用会话准备、状态构造和持久化流程；API 数据契约独立维护在 `app/api/schemas.py`。
- 统一 LLM Provider 层支持每次请求显式选择本地 Qwen 或 DeepSeek API；`/models` 返回前端安全的模型目录和配置级可用状态。
- 同步图执行、SQLite/检索准备、模型生成和媒体分析通过线程桥接进入异步服务。
- 模型生成仍使用进程内锁，保证同进程串行推理。
- `/ui` 提供响应式 Web 演示界面，采用侧边栏、居中对话流和底部输入框的成熟对话产品骨架。
- Web UI 支持模型选择与本地持久化、恢复最新活跃会话、SSE 流式回答与停止等待、基础 Markdown、来源/告警/执行详情，以及图片和视频动作上传。
- Web UI 由同一个 FastAPI 进程托管，HTML、CSS 和 JavaScript 已拆分维护，不需要额外启动 Node/Vite 前端服务。
- 微信小程序代码已覆盖对话和动作媒体上传主链路。

当前边界：

- 后端历史接口只返回用户最新活跃会话，网页侧边栏尚不支持多会话列表和切换；“停止生成”只中止前端请求等待，不保证取消已经开始的同步模型推理。
- Web UI 已有静态契约和 API 联合回归，并完成模型均未配置时的真实浏览器桌面交互验证；流式渲染、不同视口和上传链路的完整浏览器 E2E 仍待补齐。
- 模型选择不会静默跨供应商回退；当前机器没有本地 Qwen 路径，当前 Codex 进程也尚未继承可用的 DeepSeek Key，因此尚未验证一次真实 DeepSeek 生成。
- 微信开发者工具、真机、HTTPS 和弱网环境尚未完成完整验收。

### 5.1 运行模式不要混淆

| 能力 | 代码默认 | 稳定演示配置 | 说明 |
|---|---|---|---|
| 回答模型 | 默认本地 Qwen；可按请求选择 DeepSeek API | `LLM_MOCK=true` 时 `qwen-local` 使用演示回答 | DeepSeek 需要 `DEEPSEEK_API_KEY`；所选模型不可用时显式报错，不静默切换 |
| RAG | Hybrid Retriever（Dense + BM25 + RRF），Dense 默认使用 BGE + SQLite + FAISS | `RETRIEVER_STRATEGY=hybrid`、`RETRIEVER_BACKEND=sqlite_faiss` | 第一次编码可能冷启动加载 BGE；SQLite 中已有向量时可直接重建 FAISS 索引 |
| Search | 有 Tavily Key 时真实调用；缺失时 mock | 不配置或将 `TAVILY_API_KEY` 设为空 | 字面值 `mock` 会被当作真实 Key；`execution` 用于区分真实搜索和演示降级 |
| MCP | `MCP_SERVER_COMMAND=mock` | `MCP_SERVER_COMMAND=mock` | 真实 stdio Server 是可配置能力，默认演示不依赖它 |

面试演示时可以使用 Mock 保证稳定，但必须通过 `execution` 说明实际模式，不能把 Mock 数据说成真实联网、真实 MCP Server 或真实本地模型结果。

其他证据：

- Router 常规回归集 66 条。
- Router 困难样本集 36 条。
- Router 语义改写集 10 条。
- Memory + Context + RAG 专项 benchmark 为 14/14，其中 6 个多轮摘要场景覆盖早期事实、多约束、目标修改、两次增量压缩、阈值未触发和会话隔离；评测扩展还发现并修复了“内存保留 6 轮但 Prompt 只注入 3 轮”的上下文断层。
- RAG 黄金集包含 19 条可回答问题和 2 条无答案问题，全部补齐人工参考答案；主评测由 `scripts/eval_rag.py` 复用真实 Retriever 与生成节点，输出上下文相关性、回答忠实度和答案相关性三项 RAGAS 结果。`scripts/eval_retrieval.py` 保留为低成本辅助诊断，用于比较 Dense/Hybrid 的召回、排序与延迟，不作为第二套对外结论。RAGAS 入口支持逐条保存、断点续跑、生成/评分分阶段、显式检索策略和内存/SQLite + FAISS 后端；旧检查点按 Dense 口径兼容，Hybrid 应使用独立进度文件。确定性测试已证明融合、去重、来源记录和降级机制，历史 `19/19` 仍只是 Dense 冒烟；完整项目 RAGAS 尚未记录。
- 保留 SQLite + FAISS 持久化冒烟、MediaPipe 图片/视频和本地 Qwen 路由专项验证记录。

详细说明见[项目证据与验证结果](./项目证据.md)。

## 8. 本地运行

```powershell
conda activate fitness-agent
pip install -r requirements.txt
$env:LLM_MOCK="true"
$env:RETRIEVER_BACKEND="memory"
$env:MCP_SERVER_COMMAND="mock"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 9. 当前系统边界

当前版本只适合本地开发和面试演示，不能直接暴露到公网，原因包括：

- 没有登录鉴权、租户隔离和请求限流。
- `user_id` 是客户端会话键，不是安全身份凭证。
- CORS 允许任意来源。
- `/health` 只证明进程存活，不检查外部依赖。
- 本地 SQLite 和进程内缓存不支持完整多实例治理。
- 模型、Embedding/FAISS、MediaPipe、Tavily 和 MCP 都需要独立就绪检查。
- 多模型层当前只有显式选择和统一接口，没有负载均衡、自动故障转移或供应商级熔断；DeepSeek 真实生成还需在新进程正确继承用户 Key 后验收。
- Docker 尚未完成包含动作依赖和模型资产的跨机器完整验证。

## 10. 生产化演进顺序

1. 建立认证授权、用户级数据隔离、限流和审计。
2. 把模型推理拆成独立服务，增加超时、队列和资源监控。
3. 在模型可用电脑上运行 19 条完整 RAGAS，形成上下文相关性、回答忠实度和答案相关性主基线；若需定位检索问题，再辅助运行 Dense/Hybrid 的 Recall@K、MRR 与延迟对比。只有混合召回收益和延迟代价明确后，才决定是否增加 reranker，并继续扩充困难负样本。
4. 扩充标准动作、动作周期和教练标签，建立 Motion 质量评测。
5. 增强工具权限、硬超时、熔断和 MCP 进程隔离。
6. 完善长期记忆授权、删除同步、加密和多实例存储。
7. 完成小程序真机、弱网、HTTPS 和跨机器容器验收。
