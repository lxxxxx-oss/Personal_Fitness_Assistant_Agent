# 个人健身助手智能体项目总览

本文档是当前项目事实的唯一总入口。它负责说明项目是什么、代码已经做到哪里、有哪些证据、还存在哪些边界。

如果你的目标是准备面试，不要从本文开始背诵，请先阅读[文档总导航](../README.md)；如果需要学习项目话术，请阅读[项目讲解与面试话术](../learning/02_项目讲解与面试话术.md)。

## 1. 项目定位

项目的第一目标是服务智能体相关岗位面试。健身、营养和动作分析是业务场景，真正要展示的是：

- 怎样判断用户意图并选择流程。
- 怎样让大模型与知识库、搜索、算法和外部工具协作。
- 怎样管理状态、上下文和长期记忆。
- 怎样处理工具失败、依赖降级和结果追踪。
- 怎样用测试和评测验证系统。

一句话描述：

> 这是一个基于 LangGraph 的多任务智能体原型，通过受控路由把领域知识检索、实时搜索、动作分析、外部工具和记忆系统组织成可解释、可评测、可降级的执行流程。

## 2. 总体架构

系统分为四层：

```text
接入层
  FastAPI / HTTP / SSE / WebSocket / Web UI / 微信小程序
      ↓
控制层
  Router / LangGraph / 路由计划 / 子工作流
      ↓
能力层
  Knowledge / Search / Motion / MCP / ToolRegistry
      ↓
保障层
  Memory / PromptBuilder / SafetyPolicy / ToolResult / fallback / 测试与评测
```

各层职责：

| 层次 | 负责什么 | 不负责什么 |
|---|---|---|
| 接入层 | 接收请求和返回结果 | 决定任务应该怎样执行 |
| 控制层 | 判断意图、选择流程、维护共享状态 | 完成具体检索或计算 |
| 能力层 | 检索知识、搜索网络、计算动作、调用工具 | 决定整个业务流程 |
| 保障层 | 管理上下文、错误、降级和质量证据 | 替代业务能力本身 |

## 3. 用户请求怎样流转

### 普通文本请求

```text
用户问题
  -> FastAPI 接收请求
  -> Router 识别主意图、次意图和置信度
  -> 生成单路由或可靠多意图顺序计划
  -> LangGraph 调用对应子工作流
  -> 子工作流调用知识、搜索、工具或模型
  -> 写回回答、来源、警告和执行轨迹
  -> 返回最终结果
```

### 图片或视频动作请求

```text
图片 / 视频 / .npz
  -> 独立动作分析接口
  -> 姿态估计或数值文件解析
  -> 统一 PoseSequence
  -> 可选标准动作比较
  -> 结构化动作结果与提示
```

媒体上传通过独立接口执行；对话 Router 仍可以识别动作相关文本，并进入 Motion 子工作流进行规划和解释。

## 4. 当前能力状态

### 4.1 路由与图编排

当前实现：

- 顶层使用 LangGraph StateGraph 组织路由和子工作流。
- Router 支持 `search`、`motion`、`diet`、`chat`、`mcp` 兼容意图。
- 产品层将 Chat 与 Diet 统一为 Knowledge 能力域；代码层仍保留 `chat`、`diet` 两个兼容分支，分别处理普通问答和饮食建议，并共用 RAG 与上下文组件。
- 支持主意图、次意图、置信度和受控多意图计划。
- 可靠多意图按用户表达顺序执行，不再检查固定组合白名单；只允许五个已注册意图、自动去重，并限制单次最多三步。
- 当两个候选意图都达到最低分、分值接近但缺少可靠复合任务结构时，系统先返回点名差异的定向澄清；用户可选择前者、后者或“两项都要”，随后恢复对应单路或多路执行。待澄清状态按用户和会话写入 SQLite，正常会话可跨后端重启续接。
- 无规则形成稳定结论时已接入可选 embedding 样例匹配，默认关闭；当前 10 条语义改写集只能证明入口可回归，还需要更大的同义改写、hard negative 和延迟评测证明净收益后再启用。
- 本地 Qwen 分类器已完成对比验证，但默认关闭。

设计取舍：明确问题优先使用可解释、低延迟的确定性策略；合法子图可以顺序组合，但这仍是最多三步的受控编排，不是能自由生成任务、循环和依赖关系的开放式 Planner。

### 4.2 领域知识与饮食建议

当前实现：

- 本地知识库包含 12 份可索引的 `.txt/.md` 结构化文档，覆盖抗阻训练、身体活动、运动蛋白、肌酸、健康膳食、体重管理、运动补液和睡眠恢复；来源包括 WHO、CDC、ACSM、中国居民膳食指南、ISSN、NIDDK、NATA 和 AASM。内容为带来源、核验日期、适用范围和安全边界的中文摘要，不直接复制整页网页或论文。
- 分块器先解析 Markdown 标题栈，以 H2 为常规主题父边界，聚合同主题下相邻的 H3 和正文；安全、风险、禁忌等章节单独成父块，纯“来源/参考来源”章节不入索引。父块最多 500 字符，只有超长叶子拆分时使用 80 字符重叠；每个叶子章节再切成最多 180 字符、重叠 30 字符的检索子块。
- 每个子块保留 `section_path`、`parent_section_id` 和 `parent_content`；Dense 与 BM25 对子块召回，RRF 融合后按父 ID 回填父级正文并折叠同父命中，使检索粒度较细而注入 Prompt 的语境较完整。公开 API 的 `sources` 仍只返回文件来源，不改变接口契约。
- Retriever 默认采用 Hybrid 策略：Dense 向量检索与 BM25 各召回 20 条子块，经 RRF（倒数排名融合）合并，再完成父块回填与同父去重，最终返回最多 Top-5；也可通过配置关闭父子分块或切回纯 Dense。默认 Dense 后端为 SQLite + FAISS，也可切到纯内存模式。
- 默认 embedding 统一为 512 维 `BAAI/bge-small-zh-v1.5`。SQLite 持久化子块、父级正文、来源、章节、模型信息和 float32 向量；进程启动后从 SQLite 重建 FAISS `IndexFlatIP`，对归一化向量执行余弦近邻搜索。
- SQLite + FAISS 后端支持稳定主键、幂等写入、同源片段事务替换和模型/维度一致性校验；重新启动后无需重新编码即可恢复索引，避免新旧知识版本混杂。
- 入库结果会返回轻量 manifest，记录知识版本、来源、章节路径、chunk 数、chunk id 和内容哈希，便于面试时说明知识更新如何追踪。
- Chat 和 Diet 共用统一检索配置。Hybrid 主链路在融合前不做固定相似度硬过滤，Dense 与 BM25 使用相同候选预算后交给 RRF；相似度阈值只保留给纯 Dense 模式和对照评测。融合结果记录两路各自分数、排名、命中路线、来源和章节，再经去重、编号后进入 Prompt；本地持久化后端初始化、写入或检索失败时可降级到内存向量检索，并在执行轨迹中标记 `degraded`。
- 已建立 80 条 RAG 黄金集，其中 60 条可回答、20 条知识库外或证据不足问题；按 `55` 条 tuning（42 可回答）与 `25` 条 holdout（18 可回答）分开，并标注领域、难度和问法类型。项目以 `scripts/eval_rag.py` 的三项 RAGAS 结果作为对外主评测口径；`scripts/eval_retrieval.py` 不调用生成模型，仅用 Recall@K、MRR、空结果比例、延迟和分层切片辅助定位 Dense/Hybrid 的召回与排序问题，不与 RAGAS 合成总分。两条入口均已完成代码与单元测试；2026-08-08 的真实生成与评分对应上一版父子索引 v2，当前层级聚合 v3 尚未完成同口径复测。
- Knowledge 和 Diet 的检索通过 ToolRegistry 中的 `knowledge.retrieve` 执行。
- 饮食画像经过 JSON 解析和 Pydantic 范围、枚举校验。
- 非法画像不会直接进入推荐链路，而是降级为空画像并产生警告。

当前边界：层级父子分块已经落地，但仍采用确定、可复现的规则，没有引入 LLM 语义切块或 Cross-Encoder reranker。父 ID 已加入块序号和内容哈希，修复超长同名章节错误共用父块的问题；同父结果在 RRF 后折叠且暂不向后补齐，因此最终上下文可能少于 Top-5。现有资料大量采用扁平 H2，系统不会为制造大父块而跨 H2 合并，所以部分父块仍较短；进一步优化应先改善语料层级，再由黄金集决定是否引入语义聚合。知识扩充采用人工筛选权威来源、结构化改写和本地入库，不是定时联网爬虫；当前只索引 `.txt/.md`，尚未接入 PDF。SQLite + FAISS 适合单机、小规模语料，不提供分布式扩缩容或服务端索引治理。2026-08-10 的 v3 结构统计为 12 份文档、82 个子块、63 个父块，专项兼容回归通过；2026-08-08 的 Dense/Hybrid 与 RAGAS 数字属于上一版 v2，不能直接写成 v3 效果，待有完整模型的机器重建索引后复测。详细实现与版本口径见[检索实现与评测状态](./technical/rag/检索实现与评测状态.md)。

### 4.3 联网搜索

当前实现：

- 先理解并改写查询，再调用 Tavily，最后合成回答。
- 搜索结果保留标题、摘要和网址。
- 未配置密钥时可以使用演示结果。
- Search 已通过 ToolRegistry 中的 `search.tavily` 调用。
- 真实调用失败会返回可处理错误和降级信息。

当前边界：现有来源约束不等于逐句引用完全正确，后续仍需来源可信度和引用校验。

### 4.4 动作分析

当前实现：

- 支持 `.npz`、图片和短视频输入。
- MediaPipe 可将图片和视频帧转换为 33 点人体姿态。
- OpenCV 负责视频读取和抽帧。
- PoseSequence 统一保存关键点、帧率、模型、关节结构和置信度。
- 支持与兼容标准样本进行 FastDTW、余弦、对齐后逐关节平均距离、最大偏差关节/帧定位和 MediaPipe 膝/髋角度误差计算。
- 支持用关键点置信度过滤低质量关节；当有效对齐比例不足时返回低置信 warning 和 `quality.accepted=false`，全部关键点都不可用时才拒绝输出相似度结论。
- 支持从标准视频离线构建标准动作文件。
- 不兼容的姿态模型或关节结构会被拒绝。
- `motion.compare_pose` 已登记到 ToolRegistry；媒体提取由公共服务控制，已保存的结构化制品由 LangGraph 动作子图消费。
- 图片和视频接口可在显式传入 `user_id` 时，把不含原始媒体和关键点数组的结构化结果保存为短期 SQLite 制品；制品带 TTL、用户归属、可选会话绑定和软删除能力，为后续 Router 引用媒体结果提供安全边界。
- HTTP、SSE 和 WebSocket Chat 请求均可引用最多 3 个动作制品。聊天准备阶段统一校验用户、会话和有效期；有效引用会确定性进入 motion 子图并生成基于结构化摘要的解释。

当前边界：相似度和角度误差表示与参考样本的统计接近程度，不等同于专业教练或医疗诊断；正式动作库、周期切分、阶段级专项规则和教练标签仍需扩充。后端“制品引用 → Router → motion 子图”已经接通，Web UI 也已自动把上传结果附加到聊天请求并支持失败后保留附件重试；WebSocket 调用者和其他客户端仍需按接口契约显式传入制品 ID。

### 4.5 工具系统与 MCP

当前实现：

- 使用统一 `ToolResult` 和 `ErrorCode` 表达成功、失败和错误类型。
- ToolSpec 描述工具名称、说明、输入结构、权限、执行器、超时策略字段、重试和 fallback。
- ToolRegistry 支持注册、列出、参数校验、权限检查、有限重试、fallback 和审计。
- 每次执行记录 `execution_id`、`duration_ms`、尝试次数和降级来源。
- 默认登记知识检索、Tavily 搜索、动作比较和 MCP 调用四类代表工具。
- Search、Knowledge/RAG 和 MCP 执行路径已经接入注册表。
- MCP Client 支持子进程、标准输入输出、JSON-RPC 初始化、工具列表和工具调用主链路。
- 默认 MCP 使用 mock，保证本地演示稳定。

当前边界：注册表的 `timeout_seconds` 目前是策略元数据，不会强制中断长时间执行；MCP 的响应编号匹配、深层参数校验、进程隔离和真实服务兼容性仍需增强。

### 4.6 记忆与上下文

当前实现：

- 滑动窗口保存近期对话。
- 会话消息和长期记忆写入本地 SQLite。
- 会话摘要存储基础已接通：完整问答按单事务写入，active summary 可替换，`last_compacted_message_id` 记录摘要覆盖边界，并按用户与会话隔离读取。
- 已实现确定性的结构化证据摘要：只复用原始消息片段，将目标、约束、偏好映射到可追溯证据，按字符和估算 Token 双阈值触发与限长，复用上一版 active summary，并与滑动窗口统一保留最近六轮原文；默认摘要水位由模型派生的 Prompt compact Token 线按 35% 计算，并限制在 900—4000 Token，字符线同步按 4 倍派生。
- HTTP、SSE 和 WebSocket 共用会话准备与成功 turn 持久化入口；生成失败返回结构化错误且不写入历史。下一次请求会加载 active summary，并在 Chat、Diet、Search 和 MCP 最终 Prompt 中与最近对话、长期记忆分区注入。
- 长期记忆支持 CRUD、有效期、置信度、同槽位冲突替代和派生向量删除同步；检索会排除未生效、已过期或已删除记录，并结合任务类型调整排序。
- Memory Writer 支持显式“记住……”和少量稳定表达：普通显式内容直接写入长期记忆；低风险隐式信息先进入 observation，跨会话独立证据和置信度达标后自动晋升，晋升前只能作为不确定线索软注入；健康等敏感内容需要确认，口令、令牌等秘密信息拒绝持久化。
- 记忆管理页可以查看、删除正式记忆，确认或拒绝 observation，并审计、撤销可逆事件；临时对话只使用进程内最近窗口，不读取和写入持久化记忆。
- 主记忆库 SQLite 是会话和长期记忆的事实来源；可选语义增强使用独立 SQLite 向量库与进程内 FAISS 索引，默认不开启，不影响主链路。
- PromptBuilder 集中组织近期对话、active summary、长期记忆、知识证据和任务信息。
- 当前存在两类上下文压缩：回答保存后的持久化 active summary，用于跨请求保留较早会话；PromptBuilder 的本轮 Prompt compact 固定保留角色/安全规则、当前问题和已确认的伤病/过敏/禁忌等安全记忆，再将 RAG、已确认长期记忆、结构化摘要、近期对话和会话摘要组成内部有序的核心队列，按优先级逐轮各尝试一条。单条放不下时跳过并继续其他队列，一轮无新增时停止，剩余空间最后填充普通信息和软记忆，同时记录预算结果、区段用量、队列轮次和淘汰数量。
- 本轮 Prompt 预算不再使用固定经验值：启动时读取本地模型声明的上下文窗口，扣除最大生成 Token 与安全余量后得到输入硬预算，默认在其 80% 主动 compact；旧对话摘要水位再由该稳定 compact 线动态派生并设上下限，显式配置仍可覆盖。PromptBuilder 用保守估算提前控制长度，本地模型由 LLMLoader 在 chat template 后用真实 tokenizer 做最终边界校验，远程模型先检查项目字符硬上限并由 provider 校验实际模型窗口。

当前边界：会话摘要是规则驱动的结构化证据整理，不具备模型级语义归纳能力；持久化摘要和 PromptBuilder 的提前压缩仍使用保守 token 估算，只有本地模型真正推理前的最终边界使用实际 tokenizer，远程模型则依赖字符硬上限预检和 provider 返回。模型元数据不可用时会回退到安全配置，此时不能声称已测得真实上限。摘要更新也没有多实例并发锁。摘要失败不会阻塞聊天，系统继续使用最近滑动窗口和本轮临时 compact。隐式记忆只覆盖少量稳定句式，不宣称理解任意潜台词；自动晋升参数是待评测校准的原型默认值。向量同步通过本地处理接口演示，不是常驻后台 worker；登录鉴权、用户授权、加密和生产级隐私治理尚未完成。

### 4.7 Agent 安全策略

当前实现：

- 所有 LLM 入口统一注入版本化全局规则 `global-safety-v1`，再追加只能收紧边界的子图领域规则和业务任务。
- 用户输入、历史、记忆、RAG、网页和工具结果统一按不可信数据处理，不能通过其中夹带的文字覆盖安全规则、获取系统提示或提升工具权限。
- 全局与子图规则是 Prompt 压缩时的固定保留项；工具权限、参数校验和高风险确认仍由 ToolRegistry 与业务代码执行，不把 Prompt 当成授权机制。
- 非流式回答在统一出口清理内部推理、脱敏常见密钥，并拦截高置信的提示词泄露和医疗越界；SSE/WebSocket 在句段发送前使用同一规则校验。
- 安全处理版本和命中情况写入内部 Prompt 元数据、`warnings` 与 `execution`，便于测试和追踪且不暴露秘密原文。

当前边界：这是面向本项目风险的应用层纵深防御，不是完整内容审核系统或医疗安全认证；规则匹配不能覆盖所有隐晦攻击和事实错误。登录鉴权、租户隔离、限流、沙箱和生产级密钥治理仍需独立建设。

详细设计见 [Agent 安全策略设计](./technical/Agent安全策略设计.md)。

### 4.8 接口与客户端

当前实现：

- FastAPI 提供非流式 HTTP、SSE 和 WebSocket 对话接口。
- 三种聊天传输共用会话准备、状态构造和持久化流程；API 数据契约独立维护在 `app/api/schemas.py`。
- 统一 LLM Provider 层支持每次请求显式选择本地 Qwen 或 DeepSeek API；`/models` 返回前端安全的模型目录和配置级可用状态。
- 同步图执行、SQLite/检索准备、模型生成和媒体分析通过线程桥接进入异步服务。
- 模型生成仍使用进程内锁，保证同进程串行推理。
- `/ui` 提供响应式 Web 演示界面，采用侧边栏、居中对话流和底部输入框的成熟对话产品骨架。
- Web UI 支持模型选择与本地持久化、恢复最新活跃会话、SSE 流式回答与停止等待、基础 Markdown、来源/告警/执行详情，以及“图片/视频上传 → 临时制品 → Motion Router 自然语言解释”的闭环；上传或对话失败会保留附件供重试。
- Web UI 由同一个 FastAPI 进程托管，HTML、CSS 和 JavaScript 已拆分维护，不需要额外启动 Node/Vite 前端服务。
- 微信小程序代码已覆盖对话和动作媒体上传主链路。

当前边界：

- 后端和 Web UI 已支持最近会话列表、切换、新建、搜索、重命名和删除；搜索只过滤已加载的最近会话，匿名 `user_id` 也不等同于账号认证。“停止生成”只中止前端请求等待，不保证取消已经开始的同步模型推理。
- Web UI 已有静态契约和 API 联合回归，并完成 `1280×720` 真实浏览器下的长回答滚动、最近会话、搜索和菜单交互验证；真实 DeepSeek HTTP 与 SSE 的 `meta/token/done` 链路也已有记录。流式生成时主动上滚/恢复跟随、停止生成、附件上传和移动端视口仍缺完整浏览器 E2E。
- 模型选择不会静默跨供应商回退；真实 DeepSeek HTTP/SSE 曾在本机验证通过。本地 Qwen 和外部凭据是否可用取决于当前运行环境，自动化测试使用替身模型，不能据此声称当前外部服务始终就绪。
- 微信开发者工具、真机、HTTPS 和弱网环境尚未完成完整验收。

### 5.1 运行模式不要混淆

| 能力 | 代码默认 | 稳定演示配置 | 说明 |
|---|---|---|---|
| 回答模型 | 默认本地 Qwen；可按请求选择 DeepSeek API | `LLM_MOCK=true` 时 `qwen-local` 使用演示回答 | DeepSeek 需要 `DEEPSEEK_API_KEY`；所选模型不可用时显式报错，不静默切换 |
| RAG | Hybrid Retriever（Dense + BM25 + RRF），Dense 默认使用 BGE + SQLite + FAISS | `RETRIEVER_STRATEGY=hybrid`、`RETRIEVER_BACKEND=sqlite_faiss` | 第一次编码可能冷启动加载 BGE；SQLite 中已有向量时可直接重建 FAISS 索引 |
| Search | 有 Tavily Key 时真实调用；缺失时 mock | 不配置或将 `TAVILY_API_KEY` 设为空 | 字面值 `mock` 会被当作真实 Key；`execution` 用于区分真实搜索和演示降级 |
| MCP | `MCP_SERVER_COMMAND=mock` | `MCP_SERVER_COMMAND=mock` | 真实 stdio Server 是可配置能力，默认演示不依赖它 |

面试演示时可以使用 Mock 保证稳定，但必须通过 `execution` 说明实际模式，不能把 Mock 数据说成真实联网、真实 MCP Server 或真实本地模型结果。

## 6. 当前验证结果

自动化测试基线：

```text
394 passed, 1 skipped, 2 warnings
```

复现命令：

```powershell
python -m pytest -q
```

这组测试主要证明接口、状态流、工具契约、错误处理和算法可以回归。测试默认替换真实本地模型和部分 embedding，不等同于真实回答质量。

其他证据：

- Router 常规回归集 66 条。
- Router 困难样本集 36 条。
- Router 语义改写集 10 条。
- Memory + Context + RAG 专项 benchmark 为 14/14，其中 6 个多轮摘要场景覆盖早期事实、多约束、目标修改、两次增量压缩、阈值未触发和会话隔离；评测扩展还发现并修复了“内存保留 6 轮但 Prompt 只注入 3 轮”的上下文断层。
- RAG 黄金集包含 60 条可回答问题和 20 条无答案问题，全部补齐人工参考答案，并按 tuning/holdout、难度、领域和问法类型分层；主评测由 `scripts/eval_rag.py` 复用真实 Retriever 与生成节点，输出上下文相关性、回答忠实度和答案相关性三项 RAGAS 结果。`scripts/eval_retrieval.py` 保留为低成本辅助诊断，用于比较 Dense/Hybrid 的召回、排序、空结果与延迟，不作为第二套对外结论。RAGAS 入口支持分区运行、逐条保存、断点续跑、生成/评分分阶段、显式检索策略和内存/SQLite + FAISS 后端；旧检查点按 Dense 口径兼容，Hybrid 应使用独立进度文件。2026-08-08 父子索引 v2 的 Dense/Hybrid `Recall@5` 同为 `0.967`、MRR 为 `0.844/0.893`；42 条 tuning 与 18 条 holdout 的 RAGAS 结果分别为 `1.000/0.902/0.786`、`1.000/0.815/0.762`。当前 v3 尚待同口径复测。
- 保留 SQLite + FAISS 持久化冒烟、MediaPipe 图片/视频和本地 Qwen 路由专项验证记录。

详细说明见[项目证据与验证结果](./项目证据.md)。

## 9. 当前系统边界

当前版本只适合本地开发和面试演示，不能直接暴露到公网，原因包括：

- 没有登录鉴权、租户隔离和请求限流。
- `user_id` 是客户端会话键，不是安全身份凭证。
- CORS 允许任意来源。
- `/health` 只证明进程存活，不检查外部依赖。
- 本地 SQLite 和进程内缓存不支持完整多实例治理。
- 模型、Embedding/FAISS、MediaPipe、Tavily 和 MCP 都需要独立就绪检查。
- 多模型层当前只有显式选择和统一接口，没有负载均衡、自动故障转移或供应商级熔断；真实 DeepSeek 链路已有单机验证，但当前凭据可用性和长期稳定性仍需在部署环境单独检查。
- Docker 尚未完成包含动作依赖和模型资产的跨机器完整验证。

## 10. 生产化演进顺序

1. 建立认证授权、用户级数据隔离、限流和审计。
2. 把模型推理拆成独立服务，增加超时、队列和资源监控。
3. 根据 42 条可回答 tuning 的 RAGAS 基线和人工抽检，先收紧生成节点的证据约束与事实表达，再用同一调参集验证改动；参数冻结后只在 18 条可回答 holdout 上运行一次最终验证，避免把留出集变成第二个调参集。完整报告同时保留总体、切片和人工复核结果。只有现有 Hybrid 收益仍不足且失败集中在排序时，才考虑增加 reranker，不为了展示继续堆功能。
4. 扩充标准动作、动作周期和教练标签，建立 Motion 质量评测。
5. 增强工具权限、硬超时、熔断和 MCP 进程隔离。
6. 完善长期记忆授权、删除同步、加密和多实例存储。
7. 完成小程序真机、弱网、HTTPS 和跨机器容器验收。
