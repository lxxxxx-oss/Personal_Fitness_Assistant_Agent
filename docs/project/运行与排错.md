# 项目运行与排错

本文档集中维护本地开发、测试、评测、Docker 和端侧联调命令。项目能力和当前进度看 [项目总览.md](./项目总览.md)，接口参数看 [接口说明.md](./接口说明.md)。

需要启动后逐项验证网页交互、模型选择、Agent、RAG、搜索、记忆、动作分析以及 HTTP/SSE/WebSocket 时，按[手动验收测试清单](./手动验收测试清单.md)执行并记录结果；清单中的步骤是验收方法，不等同于已经通过的项目证据。

MCP 是简历和面试材料中的工具协议亮点。默认 `MCP_SERVER_COMMAND=mock` 用于离线测试和稳定演示；显式配置真实 Server 命令时，系统会走 subprocess + stdio JSON-RPC，并在连接失败时记录原因后回退 mock。

以下命令均默认在当前项目根目录执行。两台电脑的绝对路径可以不同，不要把某台机器的目录写进通用启动命令。

## 1. 快速启动

推荐使用 Python 3.11 的 `fitness-agent` Conda 环境：

```powershell
conda activate fitness-agent
pip install -r requirements.txt
$env:LLM_MOCK="true"
$env:RETRIEVER_BACKEND="memory"
$env:MCP_SERVER_COMMAND="mock"
$env:TAVILY_API_KEY=""
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

如果只做稳定网页演示，建议明确启用演示依赖，避免误把 Mock 结果当成真实外部调用：

```powershell
$env:LLM_MOCK="true"
$env:RETRIEVER_BACKEND="memory"
$env:MCP_SERVER_COMMAND="mock"
$env:TAVILY_API_KEY=""
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

以上 `$env:...` 是 PowerShell 语法；如果当前提示符是 `cmd.exe`，要改用 `set LLM_MOCK=true`、`set MCP_SERVER_COMMAND=mock` 等 `set` 命令。Web UI 和 API 由同一个 FastAPI 进程提供，不需要再启动独立前端。

本地模型运行时保持单进程、单 worker。多个 worker 会分别加载模型，可能重新引入数 GB 内存复制；同一 worker 内的子图共享 tokenizer/model，并发生成在共享模型层串行执行。HTTP/SSE/WebSocket 会把同步 LangGraph 工作放入线程，SSE/WebSocket 还通过 asyncio queue 转发 token，因此推理期间事件循环仍能处理其他 I/O；这不代表模型推理已经并行化。

### 1.1 本地 Qwen 与 DeepSeek API

回答模型支持按请求显式选择：`qwen-local` 使用本地 Qwen，`deepseek-api` 使用 DeepSeek 的 OpenAI 兼容 Chat Completions 接口。Web UI 会调用 `/models` 获取目录并禁用未配置选项；选择结果保存在当前浏览器，并随 HTTP、SSE 请求发送。

本机使用 DeepSeek 时，推荐使用标准变量名 `DEEPSEEK_API_KEY`：

```powershell
$env:DEEPSEEK_API_KEY="sk-你的密钥"
# 可选：把未显式传 model 的请求默认交给 DeepSeek
$env:LLM_DEFAULT_MODEL="deepseek-api"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Windows 用户环境变量中已存在的 `DeepSeek` 名称也可以作为兼容入口，读取优先级为 `DEEPSEEK_API_KEY` > `DeepSeek`。用户变量会持久保存，不需要每次启动设置，但新值只会被之后启动的终端、Codex 和后端进程继承；修改后应完整重启相关进程。跨平台部署仍推荐统一使用全大写标准名称，因为 Linux 环境变量区分大小写。

不要把 Key 写入源码、文档、截图或 Git。默认模型为 `deepseek-v4-flash`，可通过 `DEEPSEEK_MODEL` 覆盖。未知模型返回 400，所选模型未配置或不可用返回 503；系统不会静默切换供应商。`LLM_MOCK=true` 只让 `qwen-local` 走演示回答，不会伪装成 DeepSeek。

Windows 桌面环境也可以使用项目脚本：

```powershell
.\scripts\run_backend.cmd
```

脚本默认使用 mock MCP，日志写入：

```text
logs/uvicorn.out.log
logs/uvicorn.err.log
```

## 3. 服务检查

进程存活检查（不代表模型或外部依赖就绪）：

```powershell
curl.exe http://127.0.0.1:8000/health
```

预期返回：

```json
{"status":"ok","version":"0.1.0"}
```

Web UI：

```text
http://127.0.0.1:8000/ui
```

Web UI 由 FastAPI 直接托管 `app/static/index.html`、`styles.css` 和 `app.js`，不需要执行前端安装或构建命令。浏览器会在 `localStorage` 保存匿名演示用户 ID、当前会话 ID 和所选模型，刷新后通过历史接口恢复该用户最新的活跃会话；点击“新建对话”会归档当前活跃会话。模型选择器只保存公开模型 ID，不接触 API Key。

如果修改静态文件后页面没有变化，先使用强制刷新清理浏览器缓存，再确认访问的是当前启动进程的端口。当前侧边栏只展示一个活跃会话，这是后端历史接口的真实边界，不是前端加载失败。完整设计与已知限制见[网页端 UI 设计与实现](./technical/网页端UI设计与实现.md)。

`/health` 返回 200 只代表进程存活。内存 Retriever 第一次收到对话时可能加载 BGE 模型和本地知识，冷启动耗时可能明显高于后续请求；这时应观察 `logs/uvicorn.err.log` 是否正在加载模型，而不是立即判断服务挂死。当前项目还没有独立 `/ready` 接口，依赖就绪检查属于后续工程化项。

### 3.1 端口 8000 已被占用

如果启动时报 `Errno 10048` 或 `Only one usage of each socket address`，先不要重复启动。它通常表示已有后端进程正在监听 8000，不等于项目启动失败：

```powershell
netstat -ano | findstr :8000
curl.exe http://127.0.0.1:8000/health
```

如果 `/health` 返回 `status: ok`，直接访问 `http://127.0.0.1:8000/ui` 使用现有服务。只有确认监听进程是本项目且确实需要重启时，才根据 `netstat` 最后一列 PID 停止它，再重新运行启动命令：

```powershell
Stop-Process -Id 12345
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

不要为释放端口直接结束来源不明的进程；也可以改用 `--port 8001` 临时启动，并访问对应端口。

Dense / Hybrid 辅助诊断（不调用回答生成模型和 RAGAS 裁判，但仍需要 embedding 模型）：

```powershell
python scripts/eval_retrieval.py `
  --strategy both `
  --split all `
  --retriever-backend memory `
  --show-cases `
  --output tmp/rag_retrieval_comparison.json
```

默认对同一知识库分别运行纯 Dense 与 Hybrid；Hybrid 由 Dense Top-20、BM25 Top-20 直接进入 RRF，融合去重后返回 Top-5，融合前不做固定相似度硬过滤。`--threshold` 只作用于纯 Dense 基线。报告除全量指标外，还按 `split`、`category`、`difficulty`、`query_type` 分层输出 Recall@K、MRR、命中数和样例数，并记录 20 条无答案问题的空结果比例以及平均、P50、P95 延迟。空结果比例只描述 Retriever 是否返回文档，不是最终回答的拒答准确率。这些指标用于开发阶段定位召回、排序与性能问题，不作为第二套对外主评测，也不与 RAGAS 合成总分。

2026-08-01 本机使用本地 `bge-small-zh-v1.5`、内存后端和扩展后的 80 条黄金集完成真实对比，结果保存到 `tmp/rag_retrieval_eval_80.json`。60 条可回答样例中，Dense 与 Hybrid 均命中 `58/60`，`Recall@5=0.967`；Dense `MRR=0.844`、平均延迟 `7.28ms`，Hybrid `MRR=0.895`、平均延迟 `7.23ms`。18 条可回答留出样例上，两者 Recall@5 均为 `1.000`，Dense/Hybrid MRR 为 `0.907/0.944`。因此当前可谨慎表述为“Hybrid 没有增加 Top-5 覆盖，但把正确证据排得更靠前”；本次两路平均延迟只差 `-0.05ms`，应视为单机微基准噪声，不能据此宣称 Hybrid 更快。留出集仍小，也不能说成生产级泛化结论。

RAGAS 主评测：

```powershell
python -m pip install -r requirements-eval.txt
$env:OPENAI_API_KEY="你的裁判模型密钥"
python scripts/eval_rag.py --show-cases
```

评测入口支持用 `--retrieval-strategy dense|hybrid` 选择检索策略，用 `--split all|tuning|holdout` 选择全部、调参或留出样例，并把“真实检索与生成”和“RAGAS 裁判打分”拆开执行。每条样例完成后原子写入进度文件；进程中断后用相同的数据集、分层、检索参数和 `--progress-file` 重跑即可跳过已完成样例，配置不一致时脚本会拒绝混用旧结果。数据集和知识库按内容指纹校验，不绑定电脑上的绝对目录，因此复制同一进度文件与同一版本数据后可以跨电脑续跑。推荐先用 42 条可回答调参样例迭代，再冻结参数运行 18 条可回答留出样例；两组必须使用不同进度文件。模型资源有限时可用 `--max-new-cases` 分批生成：

```powershell
# 调参集每次最多补 5 条；重复执行会从断点继续
python scripts/eval_rag.py --split tuning --stage generate --max-new-cases 5 --progress-file tmp/rag_eval_hybrid_tuning.json

# 在裁判模型可用的机器上，只评估已生成内容
$env:OPENAI_API_KEY="你的裁判模型密钥"
python scripts/eval_rag.py --split tuning --stage score --progress-file tmp/rag_eval_hybrid_tuning.json

# 参数冻结后再跑留出集，避免用留出结果反复调参
python scripts/eval_rag.py --split holdout --progress-file tmp/rag_eval_hybrid_holdout.json
```

混合检索上线前已经存在的旧进度文件按纯 Dense 口径兼容，续跑时应显式增加 `--retrieval-strategy dense`。Hybrid 评测必须使用独立文件，例如 `--progress-file tmp/rag_eval_hybrid_progress.json`，避免把两种检索结果混到同一份报告。

如需评测当前持久化索引，显式增加 `--retriever-backend sqlite_faiss --retriever-db-path data/rag/knowledge.db`。该评测路径直接使用 `SQLiteFaissRetriever`，故意不启用业务运行时的内存 fallback：数据库、索引、写入或检索失败都会中止评测，避免把内存检索结果误记成 SQLite + FAISS 结果。脚本会以知识文件的 `source` 为单位原子替换旧 chunk，并从 SQLite 中的向量重建进程内 FAISS 索引。分阶段执行时两次命令必须保持同一组生成参数；若要重新开始，可在生成阶段增加 `--fresh`，或换一个 `--progress-file`。

本机离线裁判推荐采用“两进程、一个 Conda 环境”的轻量方式：项目与 RAGAS 继续运行在 `fitness-agent` 环境，Qwen3-8B 由 Windows 原生 `llama.cpp` 独立加载，不需要为模型再创建 Python 环境。这样可避开原生 Windows 下 AWQ 后端安装困难，也不会污染项目依赖。

`local-only` 只是满足 OpenAI 客户端的非空字段要求，不是真实密钥；服务只监听 `127.0.0.1`。embedding 参数使用本地绝对路径，避免 Hugging Face 客户端为了确认仓库文件而联网。`--reasoning off` 用于避免 Qwen3 的思考内容干扰 RAGAS 结构化评分。16 GB 显存可优先尝试 `-ngl 99` 全量 GPU offload；若启动时显存不足，先减小 `-c`，再降低 `-ngl`。如果当前终端刚安装 llama.cpp 后还找不到 `llama-server`，关闭并重新打开终端即可刷新 PATH。

`requirements-eval.txt` 将 `langchain-community` 暂时约束在 `0.4.1`：RAGAS 0.4.3 仍会导入一个在 `0.4.2` 中被移除的兼容模块。该约束只服务离线评测环境，不改变项目运行链路；RAGAS 修复上游兼容问题后可再移除。

评测集位于 `data/eval/rag_eval.jsonl`，80 条样例均带参考答案以及 `split`、`difficulty`、`query_type` 元数据。脚本使用同一个入口统一管理两个阶段：先使用显式选择的内存或 SQLite + FAISS Retriever 检索，再调用项目现有 Chat RAG 生成节点回答，最后由 RAGAS 0.4 的 collections API 输出三项分数：

- `context_relevance`：检索上下文是否与用户问题相关，对应 Retriever 质量，代码直接使用 RAGAS `ContextRelevance`。
- `faithfulness`：生成回答中的事实是否能由检索上下文支持，对应幻觉风险。
- `answer_relevance`：最终回答是否直接回应用户问题，对应端到端有效性。

三项均分只统计 60 条可回答样例；其中调参集 42 条、留出集 18 条。20 条知识库外或证据不足问题保留在数据集中，但正确拒答属于另一类能力，直接混入上述三项会把“没有相关上下文”误算成检索失败，因此脚本会明确报告其排除数量。当前 12 份可索引知识文档经过分块 v2 得到 81 个 chunk；2026-07-22 的 Top-5、阈值 0.5、旧版 `19/19` 命中只属于纯 Dense 历史冒烟。2026-08-01 的扩展集检索基线为 Dense/Hybrid `Recall@5=0.967/0.967`、`MRR=0.844/0.895`。

同日已用上述 Hybrid 参数完成两轮 42 条可回答 tuning 样例的真实生成和本地 RAGAS 评分。原始基线为 `context_relevance=1.000`、`faithfulness=0.725`、`answer_relevance=0.788`，忠实度和答案相关性的中位数为 `0.800/0.872`；增加 `grounded-v3` 证据约束并统一为确定性解码后，复测为 `1.000/0.897/0.798`，中位数为 `1.000/0.872`。新一轮 42/42 均完成且无评分失败，生成约耗时 6 分 19 秒，评分约耗时 14 分 08 秒，进度文件为 `tmp/rag_eval_hybrid_tuning_grounded_v3_20260801.json`。这能证明生成约束在 tuning 上改善了忠实度，但不是最终泛化成绩：`ContextRelevance` 会把 Top-5 拼接后做整体离散判断，`1.000` 不代表每个 chunk 都无噪声；人工复核仍发现 Top-1 排序错误、小模型残余越界和本地 8B 量化裁判假阴性。因此必须结合人工抽检解释分数，参数冻结后再只运行一次 18 条可回答 holdout。可用 `RAGAS_JUDGE_MODEL`、`RAGAS_JUDGE_EMBEDDING_MODEL`、`RAGAS_JUDGE_EMBEDDING_PROVIDER` 和 `OPENAI_BASE_URL` 替换兼容服务，密钥只从环境变量读取。

如果报告中的 Retriever mode 是 `keyword`，说明 Sentence-Transformers 模型没有成功加载；Hybrid 会只采用 BM25 结果，避免把 Dense 的关键词降级伪装成第二路召回。正常融合报告会显示 `hybrid`，并保留每条结果的命中路线与分项排名。当前默认模型是 `BAAI/bge-small-zh-v1.5`，新机器需要联网下载或预先准备 Hugging Face 缓存。`LLM_MOCK=true` 时 RAGAS 脚本会拒绝运行，因为 mock 答案没有语义评测价值。

当前 SQLite 文件同时保存 chunk、来源、章节和 float32 向量，FAISS 只负责进程内相似度检索。服务重启时会直接读取已持久化向量并重建 `IndexFlatIP`，无需再次调用 embedding 模型；写入同一 `source` 时，会在单个事务中替换该来源的旧 chunk。数据库元数据记录 embedding 模型和向量维度，不匹配时返回 `CONFIG_CONFLICT`，避免静默复用不兼容索引。安全迁移方式是：

1. 保留旧 SQLite 文件，便于回滚。
2. 将 `RETRIEVER_DB_PATH` 指向一个新文件，不要直接覆盖旧库。
3. 重启后端，让启动流程重新编码 `data/knowledge` 并写入新库。
4. 运行 RAG 检索评测和 `python scripts/smoke_sqlite_faiss.py`，确认新索引后再决定是否清理旧文件。

### RAG 分块 v2 与 SQLite + FAISS 索引

当前入库按 Markdown 标题层级、段落和句子分块，普通相邻块也保留约 80 字符重叠；`section_path` 会参与向量编码，并随检索证据进入生成 Prompt。重叠按字符近似，不是精确 token 数。

默认知识库文件为 `data/rag/knowledge.db`。首次启动会按 v2 schema 写入 `section_path`、稳定 chunk id 和向量；同一 `source` 再次入库会在事务中清理该来源的旧 chunk，避免不同版本并存。FAISS 索引不是第二份事实数据，重启后会从 SQLite 中已有的向量恢复。

如果 embedding 模型或向量维度变化，应让 `RETRIEVER_DB_PATH` 指向新的数据库文件并重新建库。这样既能保留旧索引回滚，也能避免把不同模型的向量混在同一个索引中。

## 9. 常见运行边界

- Sentence-Transformer 首次加载可能需要联网；失败时检索器降级为关键词匹配。
- Tavily API Key 缺失时 SearchTool 使用 mock 搜索结果。
- `MCP_SERVER_COMMAND` 默认为 `mock`；显式使用真实 MCP Server 时，连接失败会自动降级。
- Motion 图片入口只做单帧静态姿态摘要，不能判断完整节奏、轨迹或发力顺序。
- 本地模型适合单机演示；高并发生产环境应拆成独立模型服务。
