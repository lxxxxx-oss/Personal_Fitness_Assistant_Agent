# 上下文压缩与记忆系统实施状态

本文负责说明两套设计怎样落地、现在走到哪里。具体结构见[上下文压缩设计](./上下文压缩设计.md)和[记忆系统设计](./记忆系统设计.md)，测试结论见[项目证据](../项目证据.md)。

## 1. 为什么按这个顺序做

落地顺序是：

```text
会话可恢复
  -> Prompt 入口统一
  -> 长期记忆可管理
  -> 隐式信息可观察、敏感信息可确认
  -> 证据累积、自动晋升与撤销
  -> SQLite 基础召回
  -> 上下文 compact
  -> SQLite + FAISS 可选语义增强
  -> 统一 benchmark
```

先保证主链路可运行和可降级，再增加语义召回与治理能力；主记忆 SQLite 始终是事实源，可选语义索引不是聊天链路的单点依赖。

## 2. 当前实现

| 能力 | 当前状态 | 真实边界 |
|---|---|---|
| 会话持久化 | 已实现 | SQLite 保存完整 turn，可按 `conversation_id` 恢复 |
| 近期上下文 | 已实现 | `SlidingWindowMemory` 只作为热缓存；重启恢复当前仍先读取完整会话，再在内存中保留最近窗口 |
| 会话摘要 | 已实现原型 | 生成带 signals/evidence 的确定性 JSON 摘要，按字符或近似 token 阈值触发，不是模型语义摘要 |
| PromptBuilder | 已实现 | 统一主要文本 Prompt；总输入预算由模型声明上限动态派生，以字符和近似 token 双水位提前 compact，推理前再用真实 tokenizer 做硬校验 |
| 结构化状态 | 已实现 | 多意图步骤可共享任务、工具摘要、画像和来源 |
| 长期记忆 | 已实现原型 | 支持 CRUD、有效期/置信度、同槽位冲突替代、精确去重和派生向量删除同步 |
| 隐式观察与晋升 | 已实现规则原型 | 低风险隐式信息按来源去重并累积跨会话证据；达到证据数、会话数和置信度门槛后自动晋升，未达标时只能软注入 |
| 风险与用户控制 | 已实现原型闭环 | 敏感信息等待确认，秘密信息落库前拒绝；网页端可查看、删除、确认、拒绝和撤销。当前无登录鉴权 |
| 临时对话 | 已实现 | 只使用进程内短期窗口，不读取或写入持久化会话和长期记忆；进程重启后消失 |
| 基础召回 | 已实现 | SQLite FTS/LIKE 可独立工作 |
| SQLite + FAISS 增强 | 已实现可选链路 | 通过本地 job 处理接口演示，不是常驻 worker；使用独立数据库保存向量 |
| 上下文 compact | 已实现 | 超预算时固定保留规则、当前问题和已确认安全记忆；核心候选队列按优先级逐轮各尝试一条，放不下则跳过，剩余空间再填普通信息与软记忆；最终仍有硬预算校验，失败不阻塞聊天 |
| 联合评测 | 已实现 | Memory + Context + RAG benchmark 已建立 |

HTTP、SSE 和 WebSocket 共用持久化、摘要更新和 Prompt 构建逻辑，避免三条入口出现不同记忆行为。

## 3. 关键边界

- `compact_summary` 只表示当前会话状态，不直接写入长期记忆。
- 长期事实必须经过 Memory Writer；低风险隐式事实只有跨会话独立证据达标才会自动晋升，健康信息仍需确认，秘密信息不落库。
- 未晋升 observation 与正式长期记忆分区注入，模型被明确要求把前者视为不确定线索。
- SQLite + FAISS 是主记忆库之上的派生语义索引，加载或读写失败时降级到 FTS/LIKE。
- 当前摘要触发和 Prompt 区段裁剪仍使用字符与保守 token 估算；总输入硬边界已使用实际模型 tokenizer 精确计数，但尚未为每个区段精确分配 token 配额。
- 结构化摘要只标注可追溯 signals，不具备模型级语义归纳；隐式提取目前也是保守规则，不理解任意潜台词。
- SQLite 会持续保存完整会话，但当前重启恢复和未压缩消息定位仍会读取全量记录；按最近窗口和摘要边界进行数据库级有限查询属于未来性能优化，尚未实施。
- 当前事件表支持原型级审计和单步撤销，但用户授权、加密、多实例并发、常驻 worker 和不可抵赖审计仍属于生产化方向。

## 4. 下一步只做验证和治理

当前不需要继续扩展功能。若恢复这一专题，优先级为：

1. 扩大长会话样本，验证目标修改、无关信息和更长对话下的关键事实保留。
2. 为隐式 observation 的误写率、自动晋升准确率、冲突替代和过期清理扩大真实对话评测，并据此校准 `2/2/0.82/30天` 默认参数。
3. 根据真实误差决定是否引入模型摘要或更细的 tokenizer 分区预算，而不是预先增加复杂度。
4. 当真实长会话出现恢复瓶颈时，再实施数据库级有界恢复：按摘要边界查询未压缩消息，并只恢复 `MEMORY_MAX_TURNS * 2` 条近期原文；目标是让恢复读取量不随完整历史线性增长。

## 5. 面试回答

> 我没有把全部历史直接塞进 Prompt，而是把完整会话、近期窗口、结构化证据摘要、正式长期事实和待验证线索分层管理。低风险隐式信息只有跨会话证据和置信度达标才自动晋升，敏感信息必须确认，秘密信息不落库，自动变化可审计和撤销；临时对话则完全绕开持久化。总输入预算由模型声明上限派生，推理前再用真实 tokenizer 防止越界。当前隐式提取仍是保守规则，参数也需要更多真实对话标定。
