# RAG 检索实现与评测状态

本文记录当前代码中的 RAG 检索事实，供代码维护、故障排查和面试口径核对。历史实验数字只作为对应版本的基线，不能反向证明后续实现已经取得同样结果。

## 当前链路

```text
Markdown / 文本文档
  -> 解析 Markdown 标题栈，保留叶子章节的精确 section_path
  -> 以 H2 为常规主题父边界，聚合同一主题下相邻的 H3 / 正文
  -> 安全、风险、禁忌等章节单独成父块；纯“来源 / 参考来源”章节不入索引
  -> 父块最多 500 字符；超长叶子按 500 / 80 拆分
  -> 每个叶子章节再切成最多 180 字符、重叠 30 的检索子块
  -> 子块连同精确 section_path 参与 embedding 与 BM25 建索引

用户问题
  -> Dense 召回 20 条子块
  -> BM25 召回 20 条子块
  -> RRF 按名次融合
  -> 按 parent_section_id 回填父级正文并折叠同父子块
  -> 最多取 Top-5 上下文注入 Prompt
  -> Qwen 或 DeepSeek 基于证据生成回答
```

父子分块解决的是“检索粒度”和“阅读上下文”之间的冲突：较小子块更容易命中具体知识点，同一 H2 主题下聚合后的父块则给生成模型补回更完整语境。它不是新的检索路线；Dense、BM25 和 RRF 仍负责召回与融合，父块回填发生在融合之后。

这里没有跨 H2 强行合并。这样可以避免把相邻但语义独立的主题拼在一起，也让父块边界可解释、可复现。代价是现有资料若大量采用扁平 H2 结构，部分父块仍会较短；后续应优先优化语料标题层级，再用黄金集判断是否需要语义聚合。

## 存储与兼容

- SQLite 是知识文本、来源、章节、float32 向量、`parent_section_id` 和 `parent_content` 的持久化事实来源。
- FAISS 使用归一化向量和 `IndexFlatIP` 做进程内精确余弦检索；服务重启时从 SQLite 恢复向量和父子关系，不重新计算 embedding。
- 父 ID 同时包含块序号和内容哈希，超长同名章节拆成多个父块时不会再错误共用同一个 ID。
- 旧数据库启动时会自动补充父子字段；没有父级信息的旧记录继续返回自身内容，不会因迁移直接失效。
- `RETRIEVER_PARENT_CHILD_ENABLED=false` 可退回旧的单层结构分块，用于兼容或对照。

## 关键配置

| 配置 | 默认值 | 作用 |
|---|---:|---|
| `RETRIEVER_KNOWLEDGE_VERSION` | `v3-hierarchical` | 隔离本次层级父块索引与旧索引 |
| `RETRIEVER_CHUNK_CHARS` | `500` | 父级正文块的最大字符数 |
| `RETRIEVER_CHUNK_OVERLAP_CHARS` | `80` | 超长叶子拆成多个父块时的相邻重叠 |
| `RETRIEVER_PARENT_CHILD_ENABLED` | `true` | 是否启用父子分块与父块回填 |
| `RETRIEVER_CHILD_CHUNK_CHARS` | `180` | 检索子块的最大字符数 |
| `RETRIEVER_CHILD_CHUNK_OVERLAP_CHARS` | `30` | 检索子块的相邻重叠 |
| `RETRIEVER_CANDIDATE_K` | `20` | Dense 与 BM25 各自的候选预算 |
| `RETRIEVER_RRF_K` | `60` | RRF 排名平滑参数 |
| `RETRIEVER_TOP_K` | `5` | 最多注入的最终上下文数 |

子块重叠必须小于子块大小；配置非法时应用启动校验会直接报错。公开 Retriever 和 Tool 接口没有变化，本次只替换内部索引组织方式。

## 当前证据与评测口径

2026-08-10 的层级聚合专项回归覆盖：同一 H2 下多叶子共享父块、不同 H2 不跨界、安全章节隔离、来源章节过滤、长章节父 ID 唯一、父子关闭兼容，以及 SQLite + FAISS / Hybrid / 评测脚本兼容。两组专项命令合计 `80 passed`；这证明数据结构和检索契约可回归，不代表检索效果已经提升。

当前 12 份真实知识文档在 v3 规则下生成 82 个子块和 63 个父块。父块字符数中位数为 116、均值 137.3、最大 403；子块中位数为 94、均值 98.3、最大 176；11 个父块包含多个子块，占 17.5%。相比旧版“多数父块只有一个子块”，层级聚合已经减少父块数量并拉开最大粒度，但受扁平 H2 语料结构影响，中位数差距仍不大。

历史结果必须按版本区分：

- 2026-08-01 单层版：81 个 chunk；Dense/Hybrid `Recall@5=0.967/0.967`、`MRR=0.844/0.895`；tuning RAGAS `1.000/0.897/0.798`。
- 2026-08-08 父子分块 v2：87 个父级检索单元；Dense/Hybrid `Recall@5=0.967/0.967`、`MRR=0.844/0.893`；tuning/holdout RAGAS 分别为 `1.000/0.902/0.786`、`1.000/0.815/0.762`。
- 2026-08-10 层级聚合 v3：结构与兼容性测试已经完成，尚未重建正式 SQLite + FAISS 知识索引，也未重新运行 80 条黄金集检索评测和 RAGAS。因此不能把 v2 数字写成 v3 效果。

完整口径与运行证据见[项目证据](../../项目证据.md)。

## 已知边界

- 当前父块边界依赖 Markdown 标题质量。扁平 H2 文档不会为了制造更大父块而跨主题合并；若要进一步扩大上下文，优先重构语料标题层级或在离线评测证明收益后引入语义聚合。
- 同父子块在 RRF 后折叠，当前不会为了补足数量继续向后取候选，因此最终上下文可能少于配置的 Top-K。若业务要求固定数量，应增加折叠后的候选回填。
- 当前没有 LLM 语义切块或 Cross-Encoder reranker。是否增加复杂度应由 v3 的真实检索与 RAGAS 结果决定。
- SQLite + FAISS 适合单机、小规模知识库；多实例共享、复杂过滤和分布式扩缩容仍需迁移到服务化向量数据库。
