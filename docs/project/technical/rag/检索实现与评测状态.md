# RAG 检索实现与评测状态

本文记录当前代码中的 RAG 检索事实，供代码维护、故障排查和面试口径核对。历史实验数字只作为对应版本的基线，不能反向证明后续实现已经取得同样结果。

## 当前链路

```text
Markdown / 文本文档
  -> 识别标题层级、段落和句子边界
  -> 构造父级正文块（默认最多 500 字符，重叠 80）
  -> 再切成检索子块（默认最多 300 字符，重叠 50）
  -> 子块连同 section_path 参与 embedding 与 BM25 建索引

用户问题
  -> Dense 召回 20 条子块
  -> BM25 召回 20 条子块
  -> RRF 按名次融合
  -> 按 parent_section_id 回填父级正文并折叠同父子块
  -> 最多取 Top-5 上下文注入 Prompt
  -> Qwen 或 DeepSeek 基于证据生成回答
```

父子分块解决的是“检索粒度”和“阅读上下文”之间的冲突：较小子块更容易准确匹配具体问题，返回父级正文则保留完整语境。它不是新的检索路线；Dense、BM25 和 RRF 仍然负责召回与融合，父块回填发生在融合之后。

## 存储与兼容

- SQLite 是知识文本、来源、章节、float32 向量、`parent_section_id` 和 `parent_content` 的持久化事实来源。
- FAISS 使用归一化向量和 `IndexFlatIP` 做进程内精确余弦检索；服务重启时从 SQLite 恢复向量和父子关系，不重新计算 embedding。
- 旧数据库启动时会自动补充父子字段；没有父级信息的旧记录继续返回自身内容，不会因迁移直接失效。
- `RETRIEVER_PARENT_CHILD_ENABLED=false` 可退回旧的单层结构分块，用于兼容或对照。

## 关键配置

| 配置 | 默认值 | 作用 |
|---|---:|---|
| `RETRIEVER_CHUNK_CHARS` | `500` | 父级正文块的最大字符数 |
| `RETRIEVER_CHUNK_OVERLAP_CHARS` | `80` | 父级正文块的相邻重叠 |
| `RETRIEVER_PARENT_CHILD_ENABLED` | `true` | 是否启用父子分块与父块回填 |
| `RETRIEVER_CHILD_CHUNK_CHARS` | `300` | 检索子块的最大字符数 |
| `RETRIEVER_CHILD_CHUNK_OVERLAP_CHARS` | `50` | 检索子块的相邻重叠 |
| `RETRIEVER_CANDIDATE_K` | `20` | Dense 与 BM25 各自的候选预算 |
| `RETRIEVER_RRF_K` | `60` | RRF 排名平滑参数 |
| `RETRIEVER_TOP_K` | `5` | 最多注入的最终上下文数 |

子块重叠必须小于子块大小；配置非法时应用启动校验会直接报错。

## 当前证据与评测口径

父子分块已有单元测试覆盖：子块尺寸、同父 ID、关闭开关后的旧行为、同父命中折叠、父信息缺失时的兼容，以及 SQLite schema 元数据。它证明的是数据结构和检索契约可回归，不代表检索效果已经提升。

2026-08-01 的 81 个单层 chunk、Dense/Hybrid `Recall@5=0.967/0.967`、`MRR=0.844/0.895`，以及 tuning RAGAS `1.000/0.897/0.798`，都产生于父子分块合入之前。当前父子分块版本尚未重建正式知识索引并重新运行同一黄金集，因此不能把旧数字称为新方案的提升结果。正确的后续验证顺序是：新建 SQLite 索引文件、检查 manifest 与父子字段、运行检索专项评测、冻结参数后运行 RAGAS tuning/holdout，并与旧单层基线做对照。

## 已知边界

- 当前 `parent_section_id` 按知识版本、来源和 `section_path` 生成。同一标题下的子块会共享父 ID；如果一个超长同名章节先被拆成多个父级正文块，当前实现会保留该父 ID 首次登记的正文。正式扩大知识库前，应把父块序号或内容哈希加入父 ID，避免超长章节回填到同标题的首块。
- 同父子块在 RRF 后折叠，当前不会为了补足数量继续向后取候选，因此最终上下文可能少于配置的 Top-K。这是去重后的正常现象，但若业务要求固定数量，应增加折叠后的候选回填。
- 当前没有 LLM 语义切块或 Cross-Encoder reranker。是否增加复杂度应由父子分块版本的真实评测决定。
- SQLite + FAISS 适合单机、小规模知识库；多实例共享、复杂过滤和分布式扩缩容仍需迁移到服务化向量数据库。
