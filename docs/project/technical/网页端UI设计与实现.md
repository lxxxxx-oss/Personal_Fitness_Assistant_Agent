# 网页端 UI 设计与实现

这份文档记录 Web UI 的当前实现、接口映射和能力边界，供代码 Agent 与维护者查阅。它不是简历或面试学习材料。

## 1. 设计目标

网页端采用 ChatGPT 常见的对话交互骨架，但保留健身助手自己的内容和视觉识别：

- 桌面端使用侧边栏、顶部状态栏、居中对话流和底部输入框。
- 模型选择器位于底部输入框右侧、发送按钮左侧，只展示后端公开目录，支持在本地 Qwen 与 DeepSeek API 之间显式切换。
- 移动端将侧边栏收起为抽屉，保持输入区和主要操作可见。
- 空状态直接展示训练、饮食、动作分析和长期记忆四类示例问题。
- 回答正文保持阅读优先，来源、告警和执行轨迹放入可展开的“本次执行详情”。
- 侧边栏提供临时对话和记忆管理入口：临时对话不进入最近列表，记忆管理把正式记忆、待验证线索和事件记录分栏展示。
- 最近会话来自 SQLite 持久化与真实后端接口；仍不虚构账号系统、跨设备同步或生产级隐私能力。

这里参考的是成熟对话产品的信息层级和交互习惯，不是对 ChatGPT 视觉样式的逐像素复制。

## 2. 文件职责

| 文件 | 职责 |
|---|---|
| `app/static/index.html` | 语义化页面骨架、空状态、侧边栏、输入区、记忆管理弹窗与无障碍标签 |
| `app/static/styles.css` | 颜色、排版、消息样式、执行详情、动作卡片、记忆管理和响应式布局 |
| `app/static/app.js` | 模型目录与选择、多会话管理、临时对话、记忆生命周期操作、SSE 解析、历史恢复、Markdown 渲染、附件上传与错误处理 |
| `tests/test_web_ui.py` | 静态资源、关键 DOM 契约、API 路径和输出转义的自动化回归 |

前端仍由 FastAPI 静态托管，不需要 Node、Vite 或额外构建步骤。

## 3. 页面与接口映射

| 用户动作 | 接口 | 前端行为 |
|---|---|---|
| 打开页面 | `GET /health` | 显示服务可用、检查中或离线状态 |
| 加载模型 | `GET /models` | 展示公开模型目录，禁用未配置模型，并恢复本地保存的有效选择 |
| 加载最近会话 | `GET /chat/{user_id}/conversations` | 按最近活跃时间加载可切换的会话列表 |
| 恢复指定对话 | `GET /chat/{user_id}/conversations/{conversation_id}` | 加载指定会话的完整持久化消息并同步标题 |
| 创建对话 | `POST /chat/{user_id}/conversations` | 创建独立会话并立即加入最近列表 |
| 重命名对话 | `PATCH /chat/{user_id}/conversations/{conversation_id}` | 更新 SQLite 标题并同步侧栏与顶栏 |
| 删除对话 | `DELETE /chat/{user_id}/conversations/{conversation_id}` | 软删除指定会话；删除当前会话后自动切换或新建 |
| 开始临时对话 | `POST /chat/stream`，请求带 `temporary=true` | 生成 `tmp_` 会话 ID，只续接进程内短期窗口，不写最近会话或长期记忆 |
| 查看正式记忆 | `GET /memory` | 在记忆管理弹窗展示，可逐条删除 |
| 查看/处理线索 | `GET /memory/observations`、confirm/reject | 展示风险、置信度和证据数；敏感或不确定线索可确认或拒绝 |
| 查看/撤销事件 | `GET /memory/events`、undo | 展示记忆生命周期事件；只为可逆事件提供撤销按钮 |
| 发送消息 | `POST /chat/stream` | 优先消费 `meta`、`token`、`done`、`error` 事件并逐步渲染 |
| 流式不可用时发送 | `POST /chat` | 仅在流式请求尚未产出 token 时回退非流式接口 |
| 停止生成 | 浏览器中止当前请求 | 使用 `AbortController` 停止前端等待，不承诺取消后端已经开始的同步推理 |
| 上传图片 | `POST /motion/analyze-image` | 显示附件预览，并将结构化结果渲染为动作分析卡片 |
| 上传视频 | `POST /motion/analyze-video` | 显示上传状态，并渲染帧数、质量与建议等结构化信息 |

聊天请求显式携带 `model`，`meta` 事件返回实际选择的模型。`intent`、`sources`、`warnings` 和 `execution` 也会被消费：意图更新顶部能力标签，其他信息进入回答下方的执行详情，避免正文被工程信息淹没。流式接口在尚未产生 token 时回退 `/chat`，仍沿用同一模型 ID，不会静默切换供应商。

## 4. 会话与浏览器状态

浏览器使用三个本地键：

- `fitagent.web.user_id`：首次打开时生成稳定的匿名演示用户 ID，后续刷新继续使用。
- `fitagent.web.conversation_id`：保存当前活跃会话 ID，发送后由后端返回值校正。
- `fitagent.web.model_id`：只保存公开模型 ID，不保存或读取 API Key。

临时对话 ID 不写入 `fitagent.web.conversation_id`。刷新页面或重启后端都会退出临时模式；这是有意设计，避免“临时”状态被浏览器恢复成持久会话。

侧边栏按 `last_active_at` 展示最近活跃会话，支持新建、切换、搜索、重命名和软删除。会话操作菜单使用脱离滚动区域的浮层定位，并根据浏览器边缘自动选择展开方向，避免被侧栏裁剪。首次用户消息会自动截取前 36 个字符作为标题，用户仍可手动修改。

搜索只过滤当前已加载的最近 30 条会话，并不是服务端全文检索。浏览器生成的匿名 `user_id` 仅用于原型数据隔离，不等同于登录认证或可靠的访问控制。

## 5. 渲染与交互约束

- Markdown 先进行 HTML 转义，再处理标题、列表、代码块和行内强调，避免模型输出直接注入 HTML。
- `<think>...</think>` 推理片段不会展示给用户。
- Enter 发送，Shift+Enter 换行；输入区随内容逐行增高，达到 `150px` 上限后转为内部滚动，同时隐藏浏览器原生滚动条和 Windows 上下箭头，避免控件挤占输入区。
- 生成期间发送按钮切换为停止按钮，附件和建议卡片暂时禁用。
- 生成期间模型选择器禁用，避免一次请求中途改变模型；所有模型均未配置时显示“暂无已配置模型”并保持禁用。
- 记忆管理弹窗按“长期记忆 / 待验证线索 / 事件记录”分栏；删除、确认、拒绝或撤销成功后重新读取当前分栏，避免前端本地状态与 SQLite 分叉。
- 页面外壳保持视口高度，长回答只让中间消息区纵向滚动，不再撑高主网格后被 `body` 裁切。生成时仅当用户位于消息区底部 `80px` 范围内才自动跟随；用户主动上滚后停止抢回滚动位置。
- 页面状态通过 `aria-live`、按钮 `aria-label` 和焦点可见样式辅助键盘与读屏操作。
- 响应式断点下侧边栏变为带遮罩抽屉；系统要求减少动效时关闭非必要动画。

当前 Markdown 是原型级白名单渲染，不等同于完整 CommonMark 实现。若未来允许展示更复杂的外部内容，应换成经过安全配置的成熟 Markdown 解析和 HTML 清洗方案。

## 6. 当前验证与边界

已完成：

- `node --check app/static/app.js` JavaScript 语法检查。
- `tests/test_conversation_store.py`、`tests/test_conversation_api.py` 与 `tests/test_web_ui.py` 分别覆盖会话迁移与生命周期、用户隔离的 CRUD 接口，以及侧栏 DOM、滚动样式和前端调用契约；本次专项回归为 `16 passed`。
- `tests/test_web_ui.py tests/test_api.py tests/test_llm_providers.py` 联合回归为 `48 passed`，其中包含模型选择器位于输入区且先于发送按钮的结构契约。
- 2026-07-31 新增记忆 V2、临时对话和网页入口后，`tests/test_memory_v2.py`、`tests/test_web_ui.py` 及相关会话/记忆回归合计 `55 passed`；同时通过 `node --check app/static/app.js`。
- 本地服务访问 `/ui/` 返回 HTTP 200；真实浏览器在 `1280×720` 下确认页面外壳保持 `720px`、消息区为 `554/1782px` 的独立滚动区域，并用真实滚轮事件将 `scrollTop` 从 `0` 推进到约 `507px`。同时验证了新建会话、最近列表、搜索清空以及重命名/删除菜单展示。

尚未完成：

- 真实 SSE 流式过程中的“自动跟随—主动上滚停止跟随—回到底部恢复跟随”、停止生成和上传链路仍缺完整浏览器 E2E；当前只对跟随逻辑做了代码回归，对真实 DeepSeek HTTP 长回答完成了浏览器验收。
- 账号登录、跨设备同步与服务端会话全文检索。
- 生产级 CSP、完整 Markdown 清洗、前端错误监控与性能指标。
- “停止生成”对后端同步推理的真正取消。
- 记忆管理没有登录鉴权；当前 `user_id` 只是原型隔离键，不能把该界面当作生产级隐私控制台。

## 7. 后续实施顺序

1. 使用 Playwright 或等价方案补桌面端、移动端、流式回答、停止和上传的浏览器 E2E。
2. 为临时对话、记忆确认/撤销补真实浏览器 E2E，并验证刷新与重启边界。
3. 登录鉴权落地后，把记忆操作绑定到认证身份并补二次确认与操作审计。
4. 最后补 CSP、前端监控和大消息列表的性能优化。
