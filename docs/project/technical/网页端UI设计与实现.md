# 网页端 UI 设计与实现

这份文档记录 Web UI 的当前实现、接口映射和能力边界，供代码 Agent 与维护者查阅。它不是简历或面试学习材料。

## 1. 设计目标

网页端采用 ChatGPT 常见的对话交互骨架，但保留健身助手自己的内容和视觉识别：

- 桌面端使用侧边栏、顶部状态栏、居中对话流和底部输入框。
- 模型选择器位于底部输入框右侧、发送按钮左侧，只展示后端公开目录，支持在本地 Qwen 与 DeepSeek API 之间显式切换。
- 移动端将侧边栏收起为抽屉，保持输入区和主要操作可见。
- 空状态直接展示训练、饮食、动作分析和长期记忆四类示例问题。
- 回答正文保持阅读优先，来源、告警和执行轨迹放入可展开的“本次执行详情”。
- 不在前端虚构后端尚未提供的多会话列表、账号系统或生产级隐私能力。

这里参考的是成熟对话产品的信息层级和交互习惯，不是对 ChatGPT 视觉样式的逐像素复制。

## 2. 文件职责

| 文件 | 职责 |
|---|---|
| `app/static/index.html` | 语义化页面骨架、空状态、侧边栏、输入区与无障碍标签 |
| `app/static/styles.css` | 颜色、排版、消息样式、执行详情、动作卡片和响应式布局 |
| `app/static/app.js` | 模型目录与选择、会话状态、SSE 解析、历史恢复、Markdown 渲染、附件上传与错误处理 |
| `tests/test_web_ui.py` | 静态资源、关键 DOM 契约、API 路径和输出转义的自动化回归 |

前端仍由 FastAPI 静态托管，不需要 Node、Vite 或额外构建步骤。

## 3. 页面与接口映射

| 用户动作 | 接口 | 前端行为 |
|---|---|---|
| 打开页面 | `GET /health` | 显示服务可用、检查中或离线状态 |
| 加载模型 | `GET /models` | 展示公开模型目录，禁用未配置模型，并恢复本地保存的有效选择 |
| 恢复最近对话 | `GET /chat/{user_id}/history` | 恢复当前用户最新活跃会话和 `conversation_id` |
| 发送消息 | `POST /chat/stream` | 优先消费 `meta`、`token`、`done`、`error` 事件并逐步渲染 |
| 流式不可用时发送 | `POST /chat` | 仅在流式请求尚未产出 token 时回退非流式接口 |
| 停止生成 | 浏览器中止当前请求 | 使用 `AbortController` 停止前端等待，不承诺取消后端已经开始的同步推理 |
| 新建对话 | `DELETE /chat/{user_id}/history` | 归档当前活跃会话、清空界面和本地 `conversation_id` |
| 上传图片 | `POST /motion/analyze-image` | 显示附件预览，并将结构化结果渲染为动作分析卡片 |
| 上传视频 | `POST /motion/analyze-video` | 显示上传状态，并渲染帧数、质量与建议等结构化信息 |

聊天请求显式携带 `model`，`meta` 事件返回实际选择的模型。`intent`、`sources`、`warnings` 和 `execution` 也会被消费：意图更新顶部能力标签，其他信息进入回答下方的执行详情，避免正文被工程信息淹没。流式接口在尚未产生 token 时回退 `/chat`，仍沿用同一模型 ID，不会静默切换供应商。

## 4. 会话与浏览器状态

浏览器使用三个本地键：

- `fitagent.web.user_id`：首次打开时生成稳定的匿名演示用户 ID，后续刷新继续使用。
- `fitagent.web.conversation_id`：保存当前活跃会话 ID，发送后由后端返回值校正。
- `fitagent.web.model_id`：只保存公开模型 ID，不保存或读取 API Key。

当前历史接口只返回该用户最新的活跃会话，因此侧边栏只显示“当前会话”。点击“新建对话”会归档当前会话，而不是生成一个可随时切换的历史条目。

如果后续要支持真正的多会话侧边栏，需要先新增会话列表、按 ID 获取会话、重命名和归档接口，再扩展前端状态；不能只在浏览器中伪造列表。

## 5. 渲染与交互约束

- Markdown 先进行 HTML 转义，再处理标题、列表、代码块和行内强调，避免模型输出直接注入 HTML。
- `<think>...</think>` 推理片段不会展示给用户。
- Enter 发送，Shift+Enter 换行；输入区随内容逐行增高，达到 `150px` 上限后转为内部滚动，同时隐藏浏览器原生滚动条和 Windows 上下箭头，避免控件挤占输入区。
- 生成期间发送按钮切换为停止按钮，附件和建议卡片暂时禁用。
- 生成期间模型选择器禁用，避免一次请求中途改变模型；所有模型均未配置时显示“暂无已配置模型”并保持禁用。
- 页面状态通过 `aria-live`、按钮 `aria-label` 和焦点可见样式辅助键盘与读屏操作。
- 响应式断点下侧边栏变为带遮罩抽屉；系统要求减少动效时关闭非必要动画。

当前 Markdown 是原型级白名单渲染，不等同于完整 CommonMark 实现。若未来允许展示更复杂的外部内容，应换成经过安全配置的成熟 Markdown 解析和 HTML 清洗方案。

## 6. 当前验证与边界

已完成：

- `node --check app/static/app.js` JavaScript 语法检查。
- `tests/test_web_ui.py` 覆盖 HTML 语义骨架、独立静态资源、模型选择器、主要控件、输入框受限自动增高与隐藏原生滚动条、前端 API 路径、SSE/中止控制和输出转义。
- `tests/test_web_ui.py tests/test_api.py tests/test_llm_providers.py` 联合回归为 `48 passed`，其中包含模型选择器位于输入区且先于发送按钮的结构契约。
- 本地服务访问 `/ui/` 返回 HTTP 200；真实浏览器分别在 `1280×720` 与 `390×844` 下验证了模型选择器的位置、自适应宽度和无横向溢出，并验证“本地 Qwen 与 DeepSeek 均未配置”时的禁用选项、占位状态和零控制台错误。

尚未完成：

- 配置真实模型后的流式回答、停止生成和上传链路浏览器 E2E。
- 当前机器没有 `DEEPSEEK_API_KEY`，因此没有把真实 DeepSeek 回答质量或网络可用性计入已验证能力。
- 多会话列表与切换、账号登录、跨设备同步。
- 生产级 CSP、完整 Markdown 清洗、前端错误监控与性能指标。
- “停止生成”对后端同步推理的真正取消。

## 7. 后续实施顺序

1. 使用 Playwright 或等价方案补桌面端、移动端、流式回答、停止和上传的浏览器 E2E。
2. 后端补会话列表与按会话读取接口后，再实现真实历史侧边栏。
3. 增加长期记忆查看与候选确认入口，但避免把调试信息直接暴露给普通用户。
4. 最后补 CSP、前端监控和大消息列表的性能优化。
