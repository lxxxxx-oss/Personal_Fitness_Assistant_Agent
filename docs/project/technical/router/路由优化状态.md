# 路由系统优化状态

本文档用于快速回答：Router 现在优化到哪一步了，下一步应该先做什么。

> 当前口径：产品层按四类能力介绍，代码层保留五个 intent。Diet 负责画像与营养建议，MCP 负责标准化外部菜谱工具调用；二者同属饮食域，但执行职责不同。

单意图评分和 A/B 结论以本文为准；多意图执行结构见[多意图路由设计](./多意图路由设计.md)。`interview-archive/` 只保留历史方案，不是当前路线依据。

## 1. 一句话结论

Router 当前已经完成 Phase 1 至 Phase 4；本地 Qwen provider 已接入并完成 A/B，但默认关闭。路由层也保留了默认关闭的 embedding 样例匹配 fallback，只在没有规则达到最低分时尝试，并且必须同时通过相似度置信度和 Top1-Top2 margin。Phase 4 已支持主/次能力识别、按用户表达排序的开放合法组合、最多三步校验和最终结果合成，并补齐了两候选歧义时的定向澄清、会话级持久化与跨轮恢复。

当前准确定位是：

```text
已落地：Weighted Rules + Deterministic Ambiguity Handling + Optional Embedding Examples + Optional LLM Classifier
默认策略：真实 Qwen Router 与 embedding router 都关闭，保留 feature flag 和观测能力
当前能力：Phase 4 受控 multi-intent routing；不开放任意子图组合
```

## 2. 当前已落地能力

### 阶段 1：加权规则路由

已完成。

当前 Router 会扫描所有 intent 的规则并累加分数，而不是 first-match 命中即返回。

已落地内容：

- `WEIGHTED_RULES`
- `COMBO_RULES`
- `_apply_pattern_boosts()`
- `_route_scores`
- `_route_confidence`
- `_route_reason`
- `_route_source`

价值：

- 路由行为可解释。
- 可以看到每个 intent 的分数和命中原因。
- 能用 eval 集做回归测试。

### 阶段 2：可选 embedding 样例路由

已完成默认关闭的 embedding fallback。字符 n-gram/Jaccard 词面样例路径已经移除，避免同一层同时维护规则和另一套近似词面规则。只有设置 `ROUTER_EMBEDDING_ENABLED=1` 时，系统才会在无规则达到最低分时尝试 embedding 样例匹配。

已落地内容：

- `SEMANTIC_EXAMPLES`
- `_embedding_semantic_route()`
- `ROUTER_EMBEDDING_ENABLED`
- `ROUTER_EMBEDDING_MODEL`
- `ROUTER_EMBEDDING_MIN_CONFIDENCE`
- `ROUTER_EMBEDDING_MIN_MARGIN`
- `data/eval/router_eval.jsonl`
- `data/eval/router_semantic_rewrite_eval.jsonl`
- `scripts/eval_router.py`

当前绿色回归集：

```text
data/eval/router_eval.jsonl
66 cases
100.0% accuracy
```

语义改写补充集：

```text
data/eval/router_semantic_rewrite_eval.jsonl
10 cases
100.0% accuracy
```

embedding fallback 的接受条件：

- 只在没有规则达到 `MIN_ROUTE_SCORE` 时进入，不覆盖已经成立的确定性规则。
- 只有 `source="embedding_examples"` 才表示样例匹配通过门控并接管。
- 必须满足 `ROUTER_EMBEDDING_MIN_CONFIDENCE` 与 `ROUTER_EMBEDDING_MIN_MARGIN`。
- 模型加载或编码失败时返回 `embedding_unavailable`，不会阻塞主路由。

### 阶段 3：大模型分类兜底

已完成工程契约、观测和真实本地 Qwen provider。

已落地内容：

- `_build_llm_router_prompt()`
- `_call_llm_router()`
- `_extract_json_object()`
- `_llm_classifier_route()`
- `LLM_ROUTER_MIN_CONFIDENCE = 0.70`
- `LLM_ROUTER_ENABLED` feature flag
- LLM contract outcomes、selection outcomes 和 latency metrics

当前边界：

- `_call_llm_router()` 已接共享 `LLMLoader`，默认由 feature flag 关闭。
- 开启时只在规则和 embedding 都无法形成有效决定时调用模型。
- LLM 返回非法 JSON、非法 intent、低置信或 `needs_clarification=true` 时都会回退。
- 已有规则决定不会交给 LLM 覆盖，避免模型分类破坏稳定业务边界。

所以不能说“默认使用 LLM Router”，准确说法是：

> Phase 3 已完成真实本地模型 A/B。由于准确率没有提升且单次分类平均约 6 秒，默认保持确定性 Router；LLM provider 作为可观测、可开关的实验能力保留。

## 3. 当前评测基线

### 绿色回归集

用途：保护当前已承诺的单 intent 行为。

```text
python scripts/eval_router.py --fail-on-mismatch

Total: 66

```

这部分不应该为了优化 challenge set 被破坏。

### 困难样本集

用途：记录当前 Router 的困难边界和后续优化目标。

```text
python scripts/eval_router.py --dataset data/eval/router_challenge_eval.jsonl

Total: 36
Correct: 36
Accuracy: 100.0%
```

challenge set 已从 20 条扩充到 36 条。当前满分仍只是离线小样本结果，不能解释为生产泛化完成。

### 语义改写集

用途：验证同一意图在不同自然表达下是否保持稳定，并为后续判断 embedding 是否真的有增量收益提供样本入口。

```text
python scripts/eval_router.py --dataset data/eval/router_semantic_rewrite_eval.jsonl --fail-on-mismatch

Total: 10
Correct: 10
Accuracy: 100.0%
```

Phase 3 曾暴露并已纳入回归集的问题：

- 顺序词：`先 motion，再 search` 容易被 search 抢主意图。
- 否定约束：`不需要具体做法` 应抑制 `mcp`。
- plan-vs-motion：泛化训练计划不应误进 motion。
- diet-vs-recipe：饮食策略和具体菜谱容易互相抢。
- explicit lookup：`找一找`、`权威说法` 等检索信号还不够强。
- ambiguous plan：跨训练和饮食的综合问题更适合 chat 或澄清。

## 4. 现在到底卡在哪一步

不是卡在 Phase 1/2，它们已经完成。

当前真正的位置是：

```text
Phase 3 已完成
  -> 确定性 Router：绿色 66/66，challenge 36/36
  -> 语义改写集：10/10
  -> embedding fallback：已实现 feature flag、缓存、阈值和失败降级，默认关闭
  -> 本地 Qwen A/B：保持准确率但无净收益，默认关闭
  -> Phase 4 已完成：multi-intent 字段 + 开放合法组合 + 最多三步 + 定向澄清/恢复 + final synthesis
```

当前不再继续调 Phase 3 prompt，也不扩展为开放式 Planner。下一步应积累真实多意图请求的计划命中率、顺序准确率、组合成功率和部分失败率；embedding 是否开启也应由语义改写集、hard negative 和延迟评测决定，而不是因为“用了向量模型”就默认替换规则。
