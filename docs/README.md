# 项目文档总导航

这套文档只服务一个最终目标：把个人健身助手做成一个**能运行、能演示、能解释，并且经得住面试追问的 Agent 项目**。

为避免代码维护资料和个人学习材料互相干扰，`docs/` 只保留两个主入口：

| 入口 | 主要读者 | 负责回答什么 |
|---|---|---|
| [项目资料](./project/README.md) | Codex、Claude Code 等代码 Agent，以及维护代码的人 | 当前实现是什么、接口怎么调、如何运行、证据在哪里、技术设计如何演进 |
| [学习资料](./learning/README.md) | 你本人 | 项目怎样理解、简历怎样表达、面试官会如何追问、边界怎样防守 |

## 两套资料的关系

```text
代码与测试
   ↓ 形成可核验事实
docs/project/
   ↓ 提炼为可理解、可防守的表达
docs/learning/
```

- `project/` 是事实源，不能为了面试效果把规划写成已实现。
- `learning/` 是学习与表达层，可以适当包装亮点，但必须能回到代码、测试或明确的工程取舍。
- 两边发生冲突时，先以代码和测试为准，再修正项目资料，最后同步学习口径。
- 历史方案只用于追溯，不参与当前事实判断，也不进入第一轮学习路线。

## 最重要的一句话

> 这个项目不是为了堆叠技术名词，而是借健身场景证明能够把大模型、知识检索、工具、记忆和评测组织成一个受控、可靠、可持续演进的智能体系统。
